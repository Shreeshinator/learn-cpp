Lesson 04 · Memory and Pointers

Memory, pointers, references & smart pointers

This lesson defines program memory, addresses, the stack and heap, references, raw pointers, dynamic allocation, common lifetime errors, RAII and smart pointers, move semantics, sanitizers, and the pointer constructs encountered in C interfaces. The distinct meanings of * and & are specified precisely on first use.

1. RAM, bytes, and addresses

Definition — RAM (Random Access Memory)
Volatile working storage holding the code and data of executing programs. Contents are discarded when power is removed. Each location is identified by a numeric address.
Definition — byte
The smallest addressable unit of memory, consisting of 8 bits. An int typically occupies 4 consecutive bytes; a double typically occupies 8.
Definition — address
The numeric location of an object in memory, conventionally written in hexadecimal (prefix 0x), e.g., 0x61ff0c. The address of x is the location at which its storage begins.
Addresses:   0x61ff08      0x61ff0c      0x61ff10
             +--------+    +--------+    +--------+
             |  ????  |    |   42   |    |  ????  |
             +--------+    +--------+    +--------+
                                ^
                                |
                     int x = 42 is stored here
                     address of x = 0x61ff0c

A variable designates typed storage; its value is the data held at that storage; its address is where that storage is located. A pointer stores a memory address.

2. Storage duration: stack vs heap vs static storage

Definition — stack
Memory for objects with automatic storage duration, principally local variables. The stack stores automatic variables. Storage is created on entry to the enclosing block and released automatically at the closing }. Capacity is limited (typically on the order of 8 MB) and allocation is highly efficient.
Definition — heap
Memory for objects with dynamic storage duration allocated with new. The heap stores dynamic allocations. Lifetime is explicitly controlled: an allocation persists until released with delete. Capacity is large but manual management is required.
Definition — static storage (data segment)
Memory for objects with static storage duration: global variables and static variables. Such objects are created before main() begins and destroyed after it returns, retaining their values for the full execution.
STACK (automatic, small, fast)          HEAP (dynamic, large)
- local variables                       - allocated with new
- released at end of scope              - persists until delete is called
- int x = 5;                            - int* p = new int(5); delete p;

STATIC STORAGE (full program lifetime)
- int globalScore = 0; // namespace scope
- static int calls = 0; // retains value across calls
#include <iostream>

int globalScore = 0; // static storage: constructed before main(), destroyed after

void f(){
    int x = 10; // automatic: created here, destroyed at closing }
    int* p = new int(20); // dynamic: allocation persists until delete
    std::cout << *p << "\n"; // dereference p; prints 20
    delete p; // release is mandatory; omission produces a leak
    p = nullptr; // reset to null to prevent accidental use after release
}
int main(){ f(); }
StorageCapacity and performanceReleased byUsed for
StackSmall (approx. 8 MB), high performanceAutomatically at scope exitLocal variables, small arrays
HeapLarge, moderately lower performanceExplicit delete, or a managing smart pointerLarge objects, objects that must outlive the creating function
Static storageSmallAutomatically at program terminationGlobal variables, static state, configuration

3. The meanings of * and & by context

The same symbol performs distinct functions depending on syntactic position. The complete set is defined below.

SymbolPositionMeaningExample
* in a declarationint* p;Declares a pointer: p stores an address of an int.int* p = &x;
* in an expression*p = 100; or cout << *p;Dereference: access the object at the stored address.*p designates the pointed-to value.
& in a declarationint& ref = x;Declares a reference: ref is an alias for x.Modification of ref modifies x.
& in an expression&xAddress-of: evaluates to the address of the operand.p = &x; stores the address of x in p.
* as operatora * bMultiplication.3 * 4 evaluates to 12.
& / && as operatora & b / a && bBitwise AND / logical AND. Unrelated to pointers.if (a > 0 && b > 0)
Definition — declaration vs use
A declaration introduces a variable (int* p = ...). A use is any subsequent expression involving it (*p = 5;). Identical symbols have distinct meanings in each position.
Reading declarations: read right-to-left. int* p; reads "p is a pointer to int." int& r; reads "r is a reference to int." In expressions, *p reads "the object p points to" and &x reads "address of x."

4. References (&)

Definition — reference
An alias for an existing object. No separate object is created. The reference must be initialized at declaration and cannot be reseated to another object thereafter. Assignment through a reference modifies the referenced object.
#include <iostream>
#include <string>

void addBonus(int& score){ score += 10; }
void print(const std::string& s){ std::cout << s << "\n"; }

int main(){
    int s = 90;
    addBonus(s); // s is now 100; the function operated on the caller's object
    int& ref = s; // ref is an alias for s
    ref++;       // s is now 101
    print("hello");
}
LineDescription
void addBonus(int& score)Accepts the caller's object by reference. The & in the parameter declaration designates a reference; modifications affect the argument.
void print(const std::string& s)Accepts a large object by const reference: no copy is made, and const prohibits modification.
int& ref = s;Declares ref as an alias for s. Initialization is mandatory. A subsequent ref = other; assigns values; it does not change the binding.
Parameter selection:
• Small types not modified by the callee: pass by value (void f(int x)).
• Large types inspected but not modified: const T&.
• Objects the callee must modify: T&.
• Objects that may be absent: pointer (nullable); references always designate a valid object.

5. Raw pointers

Definition — pointer
A variable whose value is an address. Declared with *. The address is obtained with & and the pointed-to object is accessed with * (dereference). A raw pointer is an unmanaged pointer: lifetime and validity are the programmer's responsibility, in contrast to a smart pointer that enforces ownership.
int x = 42;
int* p = &x;
std::cout << p << "\n";   // prints the address, e.g. 0x61ff0c
std::cout << *p << "\n";  // prints 42: dereference accesses the pointed-to object
*p = 100;           // modifies x through the pointer; x is now 100
int* q = nullptr;   // explicitly designates no object; the correct initial state
if(q) { /* ... */ } // contextual conversion: non-null is true, nullptr is false
LineDescription
int* p = &x;Declares a pointer to int and initializes it with the address of x.
*pDereference: reading *p yields the pointed-to value; writing *p = 100 modifies it.
int* q = nullptr;Initializes the pointer to null. An uninitialized pointer holds an indeterminate value and must not be dereferenced.
Prohibited operations: dereferencing nullptr, accessing an object after delete, and omitting delete. Current practice avoids manual new/delete in favor of containers and smart pointers.

6. nullptr vs NULL

Definition — nullptr
A keyword of pointer type designating "points to no object." It is unambiguous in overload resolution.
Definition — NULL
A legacy C macro evaluating to integer 0. It converts to a null pointer but, being an integer, may select an integer overload instead of a pointer overload. Do not use it in C++.
int* p1 = nullptr; // correct: null pointer constant with pointer type
// int* p2 = NULL; // obsolete: integer zero; may resolve to the wrong overload

7. new/delete vs malloc/free

Definition — new / delete
The C++ allocation facility. new allocates storage and invokes the constructor; delete invokes the destructor and releases storage. new int[100] allocates an array of 100; it must be released with delete[].
Definition — malloc / free
The C allocation facility. malloc allocates uninitialized bytes without invoking any constructor; free releases storage without invoking any destructor. It appears in C libraries (including audio, networking, and OS interfaces) that operate outside the C++ object model. Recognize it; do not use it in C++ code.
int* a = new int(5); delete a;
int* arr = new int[100]; delete[] arr;

// C facility (no construction). Encountered in C library interfaces:
// #include <cstdlib>
// int* b = (int*)malloc(sizeof(int));
// free(b);

8. Three lifetime errors: leak, dangling pointer, double-free

Every raw-pointer lifetime defect is an instance of one of these three categories.

--- ERROR 1: LEAK (allocation never released) ---
int* b = new int(6);
// missing delete b;

  Effect: the pointer b is destroyed at scope exit, but the allocation
  persists with no pointer designating it. It is unrecoverable until
  program termination. Repeated leaks exhaust available memory.

--- ERROR 2: DANGLING POINTER / USE-AFTER-FREE ---
int* a = new int(5);
delete a;      // storage released
// *a = 1;     // invalid: a designates released storage

  Effect: writing through a after delete modifies released storage,
  producing a crash or silent corruption of a subsequent allocation.

  Correction: delete a; a = nullptr; Dereferencing nullptr fails
  deterministically rather than corrupting state. Prefer unique_ptr.

--- ERROR 3: DOUBLE-FREE ---
// delete a; ... delete a; // second release of the same allocation

  Effect: the allocator state is corrupted, typically terminating the program.
  Correction: exactly one delete per new. delete on nullptr is a safe no-op.
int* a = new int(5);
delete a;
a = nullptr; // valid: subsequent delete is a no-op; dereference fails deterministically
// *a = 1; // invalid: null dereference
int* b = new int(6);
// missing delete b; // LEAK: allocation is unrecoverable
Requirements: initialize every pointer to nullptr, release each allocation exactly once, reset the pointer after release, or use unique_ptr to enforce these properties automatically.

9. Smart pointers and RAII

Definition — RAII (Resource Acquisition Is Initialization)
A discipline in which a resource (dynamic memory, file handle, lock) is owned by an object whose destructor releases it. Acquisition occurs during construction; release occurs automatically at scope exit, including during exception unwinding. Explicit cleanup calls are unnecessary.
Definition — smart pointer
A class type that satisfies the pointer interface (->, *) while owning the pointed-to allocation and releasing it in its destructor. Three standard types exist:
Smart pointerCopyable?Release conditionApplication
unique_ptr — exclusive ownershipNo; transferable only by moveWhen the single owner is destroyedDefault selection. Use unless shared ownership is required.
shared_ptr — shared ownership with reference countYes; each copy increments the countWhen the last owner is destroyed (count reaches 0)Genuinely shared objects (e.g., a node referenced by multiple subsystems). Incurs reference-count overhead.
weak_ptr — non-owning observerYesDoes not extend lifetime; validity must be verified before useBreaking ownership cycles; caches and observers.
#include <memory>
#include <iostream>

struct Bullet { Bullet(){std::cout<<"born\n";} ~Bullet(){std::cout<<"dead\n";} };

int main(){
    auto a = std::make_unique<Bullet>(); // exclusive ownership; prints born
    // auto b = a; // ERROR — unique_ptr is non-copyable
    auto b = std::move(a); // ownership transfers to b; a becomes null
    // destruction of b at scope exit releases the object; prints dead

    auto s1 = std::make_shared<Bullet>(); // shared ownership; count = 1
    auto s2 = s1; // count = 2; both designate the same object
    // destruction order: s2 (count 2->1), s1 (count 1->0, object released)
}
LineDescription
make_unique<Bullet>()Allocates a Bullet and returns a unique_ptr<Bullet> owning it. auto deduces the pointer type. Preferred over explicit new because allocation and ownership transfer are atomic.
std::move(a)Converts a to an expiring value, authorizing transfer of ownership to b. a is null thereafter.
make_shared<Bullet>()Allocates a Bullet with an associated reference count initialized to 1. Each copy increments the count; each destruction decrements it. Release occurs at zero.
Ownership cycles: if A holds a shared_ptr to B and B holds a shared_ptr to A, the count never reaches zero and both allocations leak. Resolution: one direction holds a weak_ptr. The owning direction uses shared_ptr; the observing direction uses weak_ptr.

10. Move semantics

Definition — copy vs move
A copy duplicates the referenced state, requiring time proportional to its size. A move transfers ownership of the underlying resource, typically by copying a pointer and nullifying the source — a constant-time operation. Moves apply automatically to expiring values (temporaries) and explicitly via std::move(x), which designates x as eligible for resource transfer. A moved-from object remains in a valid but unspecified state: it may be reassigned or destroyed, but not otherwise inspected.
#include <vector>
#include <utility>
std::vector<int> make(){ std::vector<int> v(1000000,1); return v; }
int main(){
    std::vector<int> a = make(); // resource transferred from the returned temporary
    std::vector<int> b = std::move(a); // resource transferred from a; a is now empty
}

11. Sanitizers

Definition — sanitizer / Valgrind
Runtime instrumentation reporting invalid memory operations with file and line attribution. AddressSanitizer (ASan), included with g++ and clang, is enabled with -fsanitize=address -g. Valgrind is an external Linux analysis tool invoked as valgrind ./a.out. Both convert silent memory errors into precise diagnostics.
g++ -fsanitize=address -g prog.cpp && ./a.out
// -fsanitize=address enables invalid-access detection
// -g embeds line information so reports identify source locations
Recommended practice: compile exercises with -Wall -Wextra -fsanitize=address -g. Execution is slower, but use-after-free, leaks, and overflows are reported at the responsible line.

12. Pointer-to-pointer and function pointers

These constructs are infrequent in new code but appear in C interfaces, comparators, thread entry points, and callbacks. Recognition is required.

Definition — pointer-to-pointer (int**)
A pointer designating another pointer: pp -> p -> x. It permits a function to modify the caller's pointer (out-parameter) or to represent an array of pointers.
Definition — function pointer / callback
A variable storing the address of a function rather than data. It permits the caller to specify deferred behavior — e.g., a comparison function for sorting or a completion handler. C++ code generally uses std::function or lambdas; C interfaces use the raw form void(*)(int).
int x = 10;
int* p = &x;   // p designates x
int** pp = &p; // pp designates p, which designates x
**pp = 20;     // double dereference assigns x; x is now 20

void foo(int n) {}
void (*fp)(int) = &foo; // pointer to function taking int, returning void
fp(42);                 // invokes foo(42) through the pointer
ConstructMeaningEncountered in
int** pOut-parameter modifying the caller's pointer, or array of pointersC interfaces, main(int argc, char** argv)
void(*fp)(int)Callable accepting int and returning voidComparators, thread entry points, event handlers, audio callbacks
Reading rule: for **, resolve two levels of indirection. For (*fp)(...), read as "invoke the supplied function." Hand-written function pointers may be replaced with lambdas (Lessons 05/07) where the interface permits.

Exercises

  1. Reference-based swap. Implement void swap(int&, int&) using a temporary, without std::swap. In main(), verify that a=3, b=7 are exchanged after the call.
  2. Ownership transfer. Define auto p1 = std::make_unique<int>(42);. Print *p1. Execute auto p2 = std::move(p1); and verify p1 == nullptr and *p2 == 42.
  3. Manual allocation vs vector. First allocate int* arr = new int[5];, populate it with 1–5, print the contents, then execute delete[] arr; arr = nullptr;. Then repeat with std::vector<int> v = {1,2,3,4,5}; and no explicit release. Compare the safety properties.
  4. Diagnosing a leak. Write a program executing new int(1) without delete. Compile with g++ -fsanitize=address -g leak.cpp && ./a.out, identify the reported line, then correct the program with unique_ptr and confirm the report is eliminated.
  5. Classifying defects. For each of the following, identify leak, dangling pointer, or double-free: int* a = new int(5); delete a; *a = 1;; int* b = new int(6); with no delete; delete a; delete a;.
