Build your own shell (mini-bash)

Goal: implement a minimal command interpreter that prints a prompt (mysh>), reads input lines, and executes them. This project covers shell architecture, REPL, tokenization, builtins, fork, exec, wait, pipes, redirection, and history.

Overview: A shell implements a read-evaluate loop: parse input, execute builtins in-process, spawn external programs via fork/exec (POSIX) or CreateProcess (Windows). A pipe (|) connects the standard output of one process to the standard input of another.

1. Shell architecture

  • Shell — a program that displays a prompt (mysh> or $) and executes entered command lines. Examples include bash (Linux/macOS default), PowerShell (Windows), and CMD (legacy Windows).
  • Terminal — the host window providing input/output for the shell process. The shell executes as an ordinary user-space program within the terminal.
  • Kernel / OS — the kernel is the privileged core of the operating system responsible for process creation and resource management. The shell requests services via system calls (e.g. process creation).
  • Process — an executing program instance. Each process has a unique PID (process ID).
Definitions: Terminal = I/O environment. Shell = command interpreter executing within it. Process = runtime instance. Kernel = subsystem implementing system calls.

2. The REPL loop

REPL denotes Read → Eval → Print → Loop:

loop forever:
  print "mysh> "          # P: display prompt
  line = readline()       # R: read one input line
  args = split(line)      # E part 1: tokenize input
  run(args)               # E part 2: execute
  # L: repeat (while(true))
Line by line: Display the prompt to indicate readiness. Read input until newline (string). Tokenize into discrete arguments. Execute the requested operation. Repeat until termination via exit or end-of-input (Ctrl+D / Ctrl+Z).

3. Tokenization and parsing

Parsing is structured interpretation of input. Tokenization is the initial phase: splitting "g++ a.cpp -o a" into ["g++","a.cpp","-o","a"] on whitespace boundaries.

  • Token — a single lexical unit. "g++" is a token.
  • Rationale: process creation interfaces require an argument vector (argv, see Lesson 09), not a raw string. Tokenization produces that structured form.
  • This implementation splits on whitespace (spaces, tabs, newlines). It does not process quotation marks ("my file.txt" yields two tokens). Quote-aware tokenization is listed as an extension exercise.
// split() -- tokenize on whitespace
#include <sstream>
#include <vector>
#include <string>
std::vector<std::string> split(const std::string& s) {
    std::istringstream iss(s);
    std::vector<std::string> out;
    std::string w;
    while (iss >> w) out.push_back(w);
    return out;
}
Line by line:
std::istringstream iss(s); — constructs an input string stream over s, enabling formatted extraction with >>.
std::vector<std::string> out; — result container for tokens.
std::string w; — temporary holder for the current token.
while (iss >> w) — extracts successive whitespace-delimited tokens; extraction automatically skips arbitrary whitespace runs.
out.push_back(w); — appends each token. return out; returns the token vector.

4. Builtins vs external programs

Definition: Builtins execute inside the shell process (no new process). External programs are independent executables the shell launches as child processes.
  • Builtin examples: cd (modifies the shell's own working directory — this must execute in-process, as a child process cannot alter the parent's state), exit, help, pwd, echo, history.
  • External examples: g++, notepad, python — discrete files located via PATH.
  • Dispatch: if (args[0]=="cd") ... else if (args[0]=="exit") ... else // external: fork+exec. Builtins are handled by conditional branches; all other commands follow the process-creation path.

5. fork / exec / wait

On POSIX systems (Linux/macOS), launching an external program requires three operations. On Windows the API differs (see section 7); the control flow is equivalent.

  • fork() — creates a child process by duplicating the calling process. Both parent and child continue from the return point. The parent receives the child's PID (positive); the child receives 0. A return value of -1 indicates failure. The branch if (pid==0) therefore identifies child execution.
  • execvp() — replaces the current process image with a specified program. exec = execute, v = vector argument form, p = PATH search.
  • waitpid() — suspends the parent until the specified child terminates, preventing premature prompt redisplay.
BEFORE fork:                AFTER fork:                 AFTER exec in child:
+----------------+          +---------------+           +---------------+
| shell (parent) |  fork()  | shell parent  |           | shell parent  |
| pid = 100      |  ======> | pid = 100     |  exec()   | pid = 100     |
|                | duplicate+---------------+  replace  |  (waiting)    |
+----------------+          | shell CHILD   | ======>   +---------------+
                            | pid = 0       |           | g++ program   |
                            | (duplicate)   |           | (new image)   |
                            +---------------+           +---------------+
Parent then calls waitpid() until child exits, then loops.
Control flow: A single process duplicates into parent and child (fork). The child replaces its image with the target program (exec). The parent blocks in wait. When the child terminates, the parent resumes and redisplays the prompt. If fork returns -1, duplication failed. If exec returns, loading failed; the child must report via perror("exec") and terminate, otherwise two shell instances remain.
Terminology: System call = kernel service request (fork/exec/wait are system calls). perror translates the current errno value to a descriptive message. _exit(1) terminates the child immediately with status 1 without flushing parent stdio buffers (preferred over exit in the post-fork child).

6. Full shell implementation

// mysh.cpp -- g++ -std=c++17 mysh.cpp -o mysh
#include <iostream>
#include <sstream>
#include <vector>
#include <string>
#ifndef _WIN32
#include <unistd.h>
#include <sys/wait.h>
#endif
#include <filesystem>

std::vector<std::string> split(const std::string& s) {
    std::istringstream iss(s);
    std::vector<std::string> out;
    std::string w;
    while (iss >> w) out.push_back(w);
    return out;
}
int main() {
    std::string line;
    while (true) {
        std::cout << std::filesystem::current_path().string() << " mysh> ";
        if (!std::getline(std::cin, line)) break;
        auto args = split(line);
        if (args.empty()) continue;
        if (args[0] == "exit") break;
        if (args[0] == "cd") {
            if (args.size() < 2 || chdir(args[1].c_str()) != 0) perror("cd");
            continue;
        }
        if (args[0] == "help") {
            std::cout << "builtins: cd exit help\n";
            continue;
        }
#ifndef _WIN32
        pid_t pid = fork();
        if (pid == 0) {
            std::vector<char*> argv;
            for (auto& a : args) argv.push_back(a.data());
            argv.push_back(nullptr);
            execvp(argv[0], argv.data());
            perror("exec");
            _exit(1);
        } else if (pid > 0) {
            int st;
            waitpid(pid, &st, 0);
        } else {
            perror("fork");
        }
#else
        std::string cmd = line;
        if (std::system(cmd.c_str()) != 0) std::cout << "(exit != 0)\n";
#endif
    }
    return 0;
}
Part A — headers: iostream/sstream/vector/string provide console I/O, string streams, containers, and text. #ifndef _WIN32 conditionally includes POSIX headers only on non-Windows builds (_WIN32 is predefined by Windows compilers). unistd.h declares fork/exec/chdir; sys/wait.h declares waitpid. filesystem provides current_path().
Part B — split() and loop entry: split tokenizes as defined above. main takes no arguments; input arrives via standard input. std::string line; holds the current command line. while(true) implements the REPL. The prompt displays the current working directory plus mysh>. std::getline(std::cin,line) reads until newline; failure (end-of-input) terminates via break.
Part C — builtins: auto args = split(line); tokenizes. Empty input triggers continue (reprompt). exit breaks the loop. cd invokes chdir(path); .c_str() converts to null-terminated form. Missing arguments or system errors are reported via perror("cd"). continue skips process creation. help prints the builtin summary.
Part D — fork/exec/wait (POSIX): pid_t pid = fork(); duplicates the process. if (pid==0) (child): constructs a null-terminated char* vector as required by execvp (data() exposes the character buffer; final nullptr terminates the array), then replaces the image via execvp(argv[0], argv.data()). On failure, reports and calls _exit(1). else if (pid>0) (parent): blocks in waitpid(pid,&st,0) until child completion (st receives exit status). else perror("fork") handles duplication failure.
Part E — Windows fallback: The #else branch compiles on Windows: std::system(cmd.c_str()) delegates execution to the system command processor. Non-zero status prints (exit != 0). The loop then repeats. Final return 0; indicates clean termination.

7. Windows notes: CreateProcess vs system()

  • fork/exec are unavailable on Windows. The native equivalents are CreateProcessA() (creates a new process in a single call) combined with WaitForSingleObject() (blocks until completion).
  • std::system(...) delegates the full command line to the system shell (cmd.exe on Windows, /bin/sh on POSIX). It concisely handles dir, echo hi, and notepad. Trade-offs: reduced control and additional shell overhead. It is suitable for an initial implementation; direct process APIs are appropriate for subsequent refinement.
  • chdir vs _chdir: MSVC declares _chdir. MinGW/g++ accepts chdir. If chdir is unresolved, substitute _chdir.
  • Windows validation: echo hi verifies basic execution, dir verifies directory listing, notepad verifies blocking wait (the shell resumes after Notepad closes).
Recommendation: implement with system() first for cross-platform functionality, then adopt fork/exec on POSIX systems to demonstrate direct process management.

8. Pipes and dup2

Definition: A pipe (|) redirects the standard output (stdout) of one process to the standard input (stdin) of another. Example: ls | grep cpp filters directory output through pattern matching without intermediate files.
  • pipe(fd) — requests a kernel pipe, returning two file descriptors: fd[0] = read end, fd[1] = write end (fd = file descriptor, an integer handle for an open I/O channel).
  • dup2(old, new) — duplicates a file descriptor, redirecting new to reference old. dup2(fd[1], STDOUT_FILENO) redirects standard output (descriptor 1) into the pipe. STDIN_FILENO is descriptor 0.
  • Procedure for cmd1 | cmd2: create pipe → fork first child (redirect stdout to pipe write end, close unused descriptors, exec cmd1) → fork second child (redirect stdin from pipe read end, close unused descriptors, exec cmd2) → parent closes both ends → waits for both children.
  • Descriptor hygiene: all unused pipe ends must be closed. An open write end prevents end-of-file detection, causing the reader to block indefinitely.
#ifndef _WIN32
// Sketch for "cmd1 | cmd2":
// int fd[2]; pipe(fd);                 // fd[0]=read, fd[1]=write
// if (fork() == 0) {                  // first child executes left side
//     dup2(fd[1], STDOUT_FILENO);      // stdout -> pipe write end
//     close(fd[0]); close(fd[1]);
//     execvp(cmd1[0], cmd1args);
// }
// if (fork() == 0) {                  // second child executes right side
//     dup2(fd[0], STDIN_FILENO);       // stdin <- pipe read end
//     close(fd[0]); close(fd[1]);
//     execvp(cmd2[0], cmd2args);
// }
// close(fd[0]); close(fd[1]);          // parent releases descriptors
// waitpid(...); waitpid(...);          // wait for both children
#endif
Reading the sketch: each fork creates a command stage. Each dup2 remaps standard I/O to the pipe. close releases redundant descriptors to ensure correct EOF semantics. The parent closes its copies and waits for both children. Multi-stage pipelines (a | b | c) extend this pattern with chained pipes.

9. Redirection and history

  • Redirection > — redirects standard output to a file. echo hi > out.txt creates out.txt containing hi. Implementation: in the child before exec, open the file and apply dup2(fileFd, STDOUT_FILENO). > truncates; >> appends. < redirects file content to standard input.
  • Minimal redirection: freopen("out.txt","w",stdout) in the child reassigns standard output to the file. open()+dup2() provides full control for production code.
  • History — retains prior command lines for review and re-execution. Maintain std::vector<std::string> hist;, append each non-empty line, and implement a history builtin that prints numbered entries. Bound capacity (e.g. 20–100 entries) to limit memory. Interactive recall via arrow keys requires terminal libraries; print-and-retype is sufficient for this version.
# Exercise after building mysh:
mysh> echo hello > out.txt
mysh> history
# Expected: history lists prior lines including "echo hello > out.txt"
Summary: redirection is output remapping (standard output to file). History is state retention (a vector of strings). Both require minimal code once fork/exec is functional.

10. Compiling, running, and testing

# Navigate to the project directory
cd ~/Documents/CppCourse
# Windows PowerShell: cd $HOME\Documents\CppCourse

# Compile
g++ -std=c++17 mysh.cpp -o mysh

# Execute -- the shell now hosts an interactive session
./mysh
# Windows: .\mysh.exe

# Validation sequence inside mysh:
mysh> help
mysh> echo hello world
mysh> pwd
mysh> cd ..
mysh> exit
Validation rationale: help verifies builtin dispatch. echo hello world verifies external process execution. pwd/cd verify directory management. exit verifies loop termination. An exec: No such file diagnostic indicates PATH resolution failure; verify spelling or use a fully qualified path.

✅ Exercises

  1. pwd and echo builtins: pwd prints current_path(). echo prints all trailing arguments separated by spaces. This isolates builtin handling from process creation.
  2. Output redirection: implement echo hi > out.txt to create out.txt containing hi. Hint: call freopen in the child before exec, then verify file contents.
  3. Single pipe: implement ls | grep cpp (or equivalent on Windows) by detecting | in the token list, splitting into left/right command vectors, and applying the pipe procedure.
  4. Command history: maintain vector<string> hist of the last 20 entries. Implement a history builtin to display them numbered. Extension: !3 re-executes entry 3.
  5. Quote handling: extend split to preserve "my file.txt" as a single token. Hint: iterate character-by-character tracking quotation state.
