Build an audio player in C++

Goal: implement WAV file inspection and audio playback. This project covers sound representation, PCM, sample, sample rate, WAV, header, RIFF, WinMM, miniaudio, engine, and sound objects.

Overview: PCM digitizes audio at a sample rate; WAV stores a 44-byte header plus samples. Playback delivers the sample sequence to the audio device at the rate specified in the header.

1. Digital audio: PCM, sample, and sample rate

  • Sound — variation in air pressure over time. A microphone converts pressure variation to an electrical signal; a speaker performs the inverse conversion.
  • PCM (Pulse Code Modulation) — representation of audio as a sequence of amplitude measurements sampled at uniform intervals. Standard .wav files store PCM data.
  • Sample — a single amplitude measurement. Example sequence: 0, 120, -50, 300.... Commonly stored as int16 (range -32768 to 32767).
  • Sample rate — samples per second, expressed in Hz. 44100 Hz (CD quality) denotes 44100 samples per second. Higher rates increase fidelity and file size. Telephony uses 8000 Hz.
  • Channels — independent audio streams. 1 = mono, 2 = stereo (left/right).
  • Bits per sample — quantization precision per measurement. 16-bit provides 65536 levels (standard). 8-bit provides 256 levels.
  • Byte rate — sustained data throughput: sampleRate * channels * bits/8. Example: 44100×2×2 = 176400 bytes/sec.
Sound = air pressure over time (continuous).
PCM = discrete amplitude measurements, e.g. 44100 per second as int16.
  time ->  0ms   0.02ms  0.04ms  0.06ms ...
  value ->   0     120     240     180  ...
WAV file = 44-byte header + sample data.
Playback = submit samples to the audio device at the specified rate.
Interpretation: the header defines the sampling parameters; the data chunk contains the measurements. Incorrect playback rate alters pitch and duration proportionally.

2. WAV format: the 44-byte header

A .wav file consists of a header (44-byte descriptor) followed by sample data. A binary file must be accessed as raw bytes; opening WAV data as text produces unstructured output.

  • RIFF (Resource Interchange File Format) — container format. Bytes 0–3 contain RIFF, bytes 4–7 specify file size minus 8, bytes 8–11 contain WAVE.
  • fmt␣ — format subchunk identifier (bytes 12–15), followed by format parameters (channel count, sample rate, bit depth).
  • data — data subchunk identifier (bytes 36–39), followed by data size and sample bytes.
  • Little-endian — multi-byte integers stored least-significant byte first (x86 standard). Direct struct mapping on little-endian hosts requires no manual conversion.

3. Obtaining a test.wav file

  • Option A — system recorder: Windows Sound Recorder or phone voice memo. Export and rename to test.wav. Place adjacent to the executable.
  • Option B — Audacity: Generate → Tone → Export as WAV (16-bit PCM). Name the output test.wav.
  • Option C — sample archive: download a 16-bit PCM .wav file (e.g. Wikimedia Commons). Confirm the extension is .wav, not .mp3; the wavinfo implementation below supports uncompressed WAV only.
  • Placement: store in the executable's working directory (e.g. Documents/CppCourse/test.wav). A can't load file diagnostic typically indicates an incorrect working directory.

4. Windows playback with PlaySound

WinMM (Windows Multimedia) provides system audio services. PlaySoundA plays a specified file. The A suffix denotes the ANSI character-set variant. Linking with -lwinmm includes the WinMM import library.

// play_win.cpp -- g++ play_win.cpp -lwinmm -o play
#include <windows.h>
#include <mmsystem.h>
int main() {
    PlaySoundA("test.wav", NULL, SND_FILENAME | SND_SYNC);
    // SND_ASYNC = return immediately; SND_LOOP = loop
    return 0;
}
Line by line:
#include <windows.h> — core Windows API declarations.
#include <mmsystem.h> — multimedia declarations including PlaySound.
PlaySoundA("test.wav", NULL, SND_FILENAME | SND_SYNC); — plays the named file. NULL = no module handle. SND_FILENAME = first argument is a filename. | = flag combination. SND_SYNC = synchronous operation (block until completion). SND_ASYNC = asynchronous (return immediately).
Link requirement: g++ ... -lwinmm where -l specifies the winmm library. Omission produces an undefined reference to PlaySound link error.
This API is Windows-specific. For portable playback (Windows/macOS/Linux), use miniaudio as described below.

5. Reading WAV metadata with wavinfo

This utility parses and displays the header fields defined in section 2. It performs no audio output.

// wavinfo.cpp -- g++ -std=c++17 wavinfo.cpp -o wavinfo
#include <iostream>
#include <fstream>
#include <cstdint>
#pragma pack(push, 1)
struct WavHeader {
    char riff[4];
    uint32_t size;
    char wave[4];
    char fmt[4];
    uint32_t fmtLen;
    uint16_t audioFmt;
    uint16_t channels;
    uint32_t sampleRate;
    uint32_t byteRate;
    uint16_t blockAlign;
    uint16_t bits;
    char data[4];
    uint32_t dataSize;
};
#pragma pack(pop)
int main(int argc, char* argv[]) {
    if (argc < 2) {
        std::cout << "usage: wavinfo file.wav\n";
        return 1;
    }
    std::ifstream f(argv[1], std::ios::binary);
    if (!f) {
        std::cout << "cannot open file\n";
        return 1;
    }
    WavHeader h;
    f.read((char*)&h, sizeof(h));
    std::cout << "channels: " << h.channels << "\n";
    std::cout << "rate: " << h.sampleRate << "\n";
    std::cout << "bits: " << h.bits << "\n";
    std::cout << "data bytes: " << h.dataSize << "\n";
    double secs = (double)h.dataSize / h.byteRate;
    std::cout << "duration: " << secs << "s\n";
    return 0;
}
Part A — headers and struct layout:
fstream provides file stream I/O. cstdint provides fixed-width integer types such as uint32_t, matching the exact header field widths.
#pragma pack(push,1) sets 1-byte struct packing (disables compiler-inserted padding) to ensure a 44-byte layout. #pragma pack(pop) restores default packing.
struct WavHeader { ... }; declares an aggregate with members in header order. char riff[4] stores a 4-character identifier. The struct serves as a typed overlay for the first 44 file bytes.
Part B — main(): open, read, report:
if (argc < 2) — no filename supplied; prints usage and returns 1.
std::ifstream f(argv[1], std::ios::binary); — opens the file in binary mode (no newline translation; required for exact byte access).
if (!f) — open failure (invalid path); reports and exits.
WavHeader h; f.read((char*)&h, sizeof(h)); — reads 44 bytes directly into the struct. reinterpret_cast-equivalent conversion treats the struct as a byte buffer. sizeof(h) = 44. This single operation populates all fields.
Remaining statements print channel count, sample rate, bit depth, and data size. double secs = (double)dataSize / byteRate; computes duration in seconds; the cast to double preserves fractional precision.
g++ -std=c++17 wavinfo.cpp -o wavinfo
./wavinfo test.wav
# Windows: .\wavinfo.exe test.wav
# Expected: channels: 2, rate: 44100, bits: 16, data bytes: ..., duration: ...s
Validation: execute against multiple WAV files and compare dataSize and duration. Longer recordings yield proportionally larger dataSize values.

6. Cross-platform playback with miniaudio

miniaudio is a single-header audio library (miniaudio.h) supporting Windows/macOS/Linux output and WAV/MP3/FLAC decoding. Single-header library = distribution as one header file placed adjacent to the source; no separate installation required. Two core abstractions: engine = initialized audio subsystem (initialized once); sound = a loaded audio resource within the engine (multiple sounds per engine permitted).

// player.cpp -- g++ -std=c++17 player.cpp -o player
#define MINIAUDIO_IMPLEMENTATION
#include "miniaudio.h"
#include <iostream>
#include <string>
int main(int argc, char* argv[]) {
    if (argc < 2) {
        std::cout << "usage: player file.wav\n";
        return 1;
    }
    ma_engine engine;
    if (ma_engine_init(NULL, &engine) != MA_SUCCESS) {
        std::cout << "engine fail\n";
        return 1;
    }
    ma_sound sound;
    if (ma_sound_init_from_file(&engine, argv[1], 0, NULL, NULL, &sound) != MA_SUCCESS) {
        std::cout << "can't load file\n";
        return 1;
    }
    ma_sound_start(&sound);
    std::cout << "Playing " << argv[1] << " -- press Enter to toggle, q+Enter to quit\n";
    std::string line;
    bool playing = true;
    while (std::getline(std::cin, line)) {
        if (line == "q") break;
        playing = !playing;
        if (playing) ma_sound_start(&sound);
        else ma_sound_stop(&sound);
        std::cout << (playing ? "playing\n" : "paused\n");
    }
    ma_sound_uninit(&sound);
    ma_engine_uninit(&engine);
    return 0;
}
Line by line:
#define MINIAUDIO_IMPLEMENTATION — enables implementation inclusion; required in exactly one translation unit before the header.
#include "miniaudio.h" — quoted form searches the source directory first. Obtain miniaudio.h from the upstream repository and place it alongside player.cpp.
if (argc < 2) — missing filename; prints usage and exits.
ma_engine engine; — declares the audio subsystem instance. ma_ is the miniaudio prefix.
ma_engine_init(NULL, &engine) — initializes with default configuration (NULL = defaults; second argument receives the initialized engine). Return value must equal MA_SUCCESS.
ma_sound sound; — declares a sound slot.
ma_sound_init_from_file(&engine, argv[1], 0, NULL, NULL, &sound) — decodes the specified file into the sound object (default flags/group). Failure indicates missing or unsupported input.
ma_sound_start(&sound); — begins playback; samples stream to the audio device at the header-specified rate.
bool playing = true; — bool playback-state flag.
while (getline(cin,line)) — per-line control: q terminates (break); otherwise inverts state (!playing), calls ma_sound_start or ma_sound_stop accordingly, and reports status.
ma_sound_uninit / ma_engine_uninit — releases the sound resource, then shuts down the engine.
Additional controls: ma_sound_set_volume(&sound, 0.5f); sets 50% volume (1.0 = full scale, 0.0 = mute; f = float literal). ma_sound_get_cursor_in_seconds(&sound, &cur); and ma_sound_get_length_in_seconds(&sound, &len); report playback position and duration. ma_sound_seek_to_second(&sound, 30); seeks to 30 seconds.

7. Playlist player implementation sequence

After single-file playback functions, extend to directory-based playback in the following order:

  1. Enumerate audio files: for (auto& e : std::filesystem::directory_iterator("music")) filtering to .wav/.mp3 extensions (same classification approach as Lesson 09). Store results in vector<string>.
  2. Transport commands: implement next, prev, list. next stops and uninitializes the current sound, initializes the subsequent file, and starts playback. Maintain an index i for position.
  3. Volume control: + / - adjust ma_sound_set_volume in 0.1 increments. Display the resulting value.
  4. Progress display: report cursor / length in seconds using the position/length query functions above.
Sequencing rationale: file enumeration validates filesystem handling. Transport commands validate engine reuse. Volume and progress exercise the extended API. Implement and test incrementally.

8. Compiling and running

# 2. Navigate to the project directory
cd ~/Documents/CppCourse

# 3. Compile
g++ -std=c++17 wavinfo.cpp -o wavinfo
g++ -std=c++17 player.cpp -o player
# Windows PlaySound variant only:
g++ play_win.cpp -lwinmm -o play

# 4. Execute
./wavinfo test.wav
./player test.wav
# Windows: .\wavinfo.exe test.wav  and  .\player.exe test.wav
Diagnostics: miniaudio.h: No such file indicates the header is not in the source directory. can't load file indicates an incorrect filename or working directory (verify with directory listing). Audible failure without errors typically indicates muted output or incorrect device selection; verify OS mixer settings and output device.

✅ Exercises

  1. Metadata comparison: run wavinfo on three files. Record sample rate, channel count, bit depth, and duration. Sum durations to compute total playlist length.
  2. Signal synthesis: generate a 440 Hz sine WAV (concert A). Write the 44-byte header from section 2 with binary output, then compute per-sample values as sin(2*3.14159*440*t) scaled to int16 range. Verify with the miniaudio player.
  3. Volume controls: add + (increase) and - (decrease) handling to the miniaudio player using ma_sound_set_volume. Display volume after each adjustment.
  4. Transport commands: replace Enter-toggle with explicit p (pause), r (resume), and q (quit) commands.
