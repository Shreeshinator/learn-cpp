DSA: How to Store Data and How to Work With It Fast

This lesson covers DSA from first principles. DSA means Data Structures + Algorithms. The distinction matters because all performance decisions in this lesson follow from it.

Definition: Data Structure
A data structure is a defined organization of data in memory, with explicit trade-offs for access, insertion, deletion, and memory overhead. In C++, vector, linked lists, stack, queue, trees, and hash tables are standard options. They store the same logical data but provide different operation costs.
Definition: Algorithm
An algorithm is a finite, unambiguous sequence of steps that transforms input into output. For example, linear search examines each element in sequence until the target is found or the input is exhausted. Sorting algorithms reorder a sequence into ascending or defined order.
Why DSA matters
Small inputs tolerate any implementation. With 1,000 or 1,000,000 records — messages, entities, files, rows — the choice of structure and algorithm determines whether an operation completes in milliseconds or becomes impractical. DSA is the discipline of selecting representations and procedures whose scaling behavior fits the workload.

1. Big-O: how runtime grows with input size

Big-O describes how runtime grows with input size. It expresses the number of operations as a function of n, where n is the number of input elements, abstracting away hardware and constant factors.

Two reference cases:

  • Direct access: retrieving an element by index requires one step regardless of collection size. This is O(1).
  • Sequential scan: examining each element in order requires up to n steps. This is O(n).

In Big-O notation, O denotes order of growth and n denotes input size. O(n) means cost grows proportionally with n. O(1) means cost remains constant as n grows.

Definition: n
n is the input size. For a vector<int> v containing 1,000,000 integers, n = 1,000,000. Big-O analysis asks how time and space requirements change as n increases.
Definition: constant, logarithmic, linear, quadratic growth
  • Constant O(1): cost is independent of n.
  • Logarithmic O(log n): cost grows slowly because each step reduces the remaining problem by a constant fraction, typically one half.
  • Linear O(n): cost grows proportionally with n. Doubling the input doubles the work.
  • Quadratic O(n²): cost grows proportionally to n multiplied by n. Doubling the input quadruples the work.

Search cost comparison

Consider locating a specific value in a collection of 1,000,000 sorted entries:

  • Sequential scan: examine entries from first to last. Worst case 1,000,000 comparisons. This is O(n) — linear search. It requires no preconditions but scales linearly.
  • Binary search: examine the midpoint, discard the half that cannot contain the target, and repeat on the remaining interval. Approximately 20 comparisons suffice for 1,000,000 entries, since 2²⁰ ≈ 1,048,576. This is O(log n). It requires sorted input.
  • Indexed access: when the position is known, retrieve it directly, e.g. v[402]. This is O(1).

Definition: worst case
Big-O conventionally describes the worst case — the maximum cost over all inputs of size n, such as a target located at the final position or absent entirely. A fast worst case guarantees acceptable behavior for all inputs.

2. Linked lists: sequences of nodes linked by pointers

A linked list is a sequence of nodes linked by pointers. A vector stores elements in contiguous memory and supports O(1) indexed access. A linked list stores elements in independently allocated nodes, each containing a value and the address of the next node.

Each node contains two fields: (1) a stored value such as 10, and (2) a pointer to the successor node. In C++ this element is conventionally defined as Node.

Definition: node, pointer, nullptr, head, heap allocation
  • Node — one element of the list, holding data plus a pointer to the next node.
  • Pointer (Node*) — a variable holding a memory address. The * indicates the variable stores an address rather than a value.
  • nullptr — a pointer value indicating no target. It terminates the list.
  • head — pointer to the first node. Loss of the head pointer makes the list unreachable.
  • Heap allocation with new / delete — dynamic storage that persists until explicitly released. Each node is created with new and must later be released with delete to avoid a leak.

Structure of a three-node list holding 1 → 2 → 3:

head
  |
  v
+-----+    +-----+    +-----+
| 1| *---->| 2| *---->| 3| null |
+-----+    +-----+    +-----+
  Node       Node       Node
  val=1      val=2      val=3
  next=addr  next=addr  next=nullptr

The * in each box denotes the next pointer. The final node stores nullptr.

#include <iostream>

// A Node holds a value and the address of the successor node.
struct Node {
    int val;      // stored value
    Node* next;   // address of successor, or nullptr if last

    // Construct a Node holding v with no successor.
    Node(int v): val(v), next(nullptr) {}
};

int main() {
    // 1. Allocate the first node holding 1. head addresses it.
    Node* head = new Node(1);

    // 2. Allocate the second node holding 2 and link it from head.
    head->next = new Node(2);
    // head->next means: access head, then follow its next pointer.
    // -> dereferences the pointer and accesses the member.

    // 3. Allocate the third node holding 3 after the second.
    head->next->next = new Node(3);

    // 4. Traverse: begin at head, advance until nullptr.
    // c denotes the current node; c = c->next advances one position.
    for (Node* c = head; c != nullptr; c = c->next) {
        std::cout << c->val << " "; // output the current value
    }
    std::cout << "\n";

    // 5. Release each allocation to avoid a leak.
    // t preserves the current head before advancing,
    // so the prior node can be deleted safely.
    while (head != nullptr) {
        Node* t = head;       // record node to delete
        head = head->next;    // advance head to successor
        delete t;             // return memory to the system
    }
    return 0;
}

Selection criteria: Prefer vector when indexed access by position is required (O(1)). Prefer a linked list when frequent insertion and deletion occur away from the end and indexed access is not required. In production code use std::list or std::forward_list; implement a list manually once to establish pointer mechanics.

3. Stacks (LIFO) and queues (FIFO)

Stacks and queues are access disciplines applied to a sequence, not distinct storage mechanisms.

  • Stack — LIFO. LIFO means Last In, First Out. push appends an element, pop removes the most recently added element, and top observes it. Only the most recent element is directly accessible.
  • Queue — FIFO. FIFO means First In, First Out. Elements are appended at the back (push/enqueue) and removed from the front (pop/dequeue). The longest-resident element is served first.
Definition: push, pop, top, front
push(x) inserts x. pop() removes an element — the newest for a stack, the oldest for a queue. In C++ pop() removes without returning the value. Observe the value first with top() (stack) or front() (queue), then call pop().
#include <stack>   // LIFO discipline
#include <queue>   // FIFO discipline
#include <iostream>
#include <string>

int main() {
    // --- Stack demo ---
    std::stack<int> st; // empty stack of ints
    st.push(1); // stack: [1]
    st.push(2); // stack: [1, 2], 2 is on top
    std::cout << st.top() << "\n"; // 2 (observation, no removal)
    st.pop();   // remove 2. stack is now [1]
    std::cout << st.top() << "\n"; // 1

    // --- Queue demo ---
    std::queue<int> q; // empty queue of ints
    q.push(1); // queue: [1]
    q.push(2); // queue: [1, 2] (1 is front, 2 is back)
    std::cout << q.front() << "\n"; // 1 (oldest element)
    q.pop();   // remove 1. queue is now [2]
    std::cout << q.front() << "\n"; // 2

    // --- Standard stack application: bracket balance check for "{[()]}" ---
    // On an opening bracket, push it. On a closing bracket,
    // it must correspond to the current top; if so, pop.
    std::string s = "{[()]}";
    std::stack<char> b;
    for (char c : s) {
        if (c == '(' || c == '[' || c == '{') {
            b.push(c); // opening bracket: record pending closer
        } else {
            // closing bracket: verify against top, then pop
            // (full matching logic omitted here — complete as exercise)
            if (!b.empty()) b.pop();
        }
    }
    std::cout << (b.empty() ? "balanced" : "not balanced") << "\n";
    return 0;
}
Typical applications: Stacks support undo history (most recent action reversed first), call management, bracket validation, and backtracking. Queues support print scheduling, message buffering, breadth-first search, and any workload requiring first-come-first-served order.

4. Sorting and searching

Sorting arranges elements in defined order (numeric ascending, lexicographic). Searching locates a target value. The central result: sorted input permits binary search, which reduces search cost from O(n) to O(log n).

4a. Sorting — use std::sort; study bubble sort once

Definition: std::sort, bubble sort, swap
  • std::sort — the standard efficient sort (O(n log n)). Use it in production code.
  • Bubble sort — an instructional O(n²) sort. It performs repeated passes, swapping each adjacent out-of-order pair so the maximum unsorted value settles at the end of the range per pass.
  • swap(a,b) — exchanges two values. std::swap(v[j], v[j+1]) exchanges two vector positions.
#include <vector>
#include <algorithm> // for std::sort and std::swap
#include <iostream>

// Bubble sort: instructive, not suitable for large n.
// Each pass places the largest remaining value at the end of the unsorted prefix.
void bubble(std::vector<int>& v) {
    // v.size() is the element count. size_t is an unsigned size type.
    for (size_t i = 0; i < v.size(); i++) {
        // After i passes, the final i positions are ordered, so exclude them (- i).
        // j+1 bound prevents access past the end.
        for (size_t j = 0; j + 1 < v.size() - i; j++) {
            if (v[j] > v[j + 1]) {
                std::swap(v[j], v[j + 1]); // adjacent inversion -> exchange
            }
        }
    }
}

int main() {
    std::vector<int> v = {5, 2, 9, 1};
    bubble(v); // instructional sort — result: 1 2 5 9
    // Production equivalent (O(n log n)):
    // std::sort(v.begin(), v.end());
    for (int x : v) std::cout << x << " ";
    std::cout << "\n";
    return 0;
}
LineExplanation
for (i ...) outer loopExecutes n passes. Pass 0 fixes the maximum at the final position; pass 1 fixes the next maximum, and so on.
for (j ... v.size()-i) inner loopScans left to right comparing adjacent pairs. The - i term excludes the already-ordered suffix.
if (v[j] > v[j+1]) swapIf the left element exceeds the right, the pair is inverted — exchange them. After a complete pass, the maximum has propagated to the end.
Why O(n²)?n passes × n comparisons per pass ≈ n×n operations. For n=1M this is on the order of a trillion — hence std::sort for real workloads.

4b. Binary search on sorted data

Binary search locates a target in sorted input by repeatedly examining the midpoint of the remaining interval. If the midpoint equals the target, the search terminates. If the midpoint is less than the target, the lower half is discarded; otherwise the upper half is discarded. Each comparison halves the remaining range.

Definition: binary search, sorted order, lo / hi / mid, O(log n)
  • Binary search — interval-halving search. Each step selects one of two halves and discards the other.
  • Sorted — arranged in order. Binary search requires sorted input. Sort first or use linear scan for unsorted data.
  • lo / hi / mid — lower bound index, upper bound index, and midpoint index. Together they delimit the current search interval.
  • Approximately 20 steps suffice for n=1M because repeated halving reaches one element after ~20 divisions (2²⁰ ≈ 1,048,576).
#include <vector>
#include <algorithm>
#include <iostream>

// Return index of target in sorted vector v, or -1 if absent.
// const & borrows v without copying (efficient) and prohibits modification.
int binarySearch(const std::vector<int>& v, int target) {
    int lo = 0;                // lower bound of search interval
    int hi = (int)v.size() - 1; // upper bound of search interval

    while (lo <= hi) {       // while interval is non-empty
        int mid = lo + (hi - lo) / 2; // midpoint (overflow-safe form)
        if (v[mid] == target) {
            return mid;        // target located; return position
        } else if (v[mid] < target) {
            lo = mid + 1;      // midpoint below target -> discard lower half
        } else {
            hi = mid - 1;      // midpoint above target -> discard upper half
        }
    }
    return -1; // interval exhausted without match -> absent
}

int main() {
    std::vector<int> v = {5, 2, 9, 1};
    std::sort(v.begin(), v.end()); // Required precondition: v becomes 1 2 5 9
    std::cout << binarySearch(v, 9) << "\n"; // prints 3 (index of 9)
    std::cout << binarySearch(v, 7) << "\n"; // prints -1 (absent)
    return 0;
}
LineExplanation
lo=0, hi=size-1Initializes the interval to the full index range.
mid = lo+(hi-lo)/2Computes the midpoint of the current interval. This form avoids overflow for large bounds, unlike (lo+hi)/2.
v[mid]==target → return midMidpoint equals target — search complete; return its index.
v[mid] < target → lo=mid+1Midpoint below target — all positions through mid are excluded; continue on the upper half.
else hi=mid-1Midpoint above target — continue on the lower half.
return -1Interval is empty and the target was not encountered. -1 conventionally signals absence since valid indices begin at 0.

5. Trees and hash tables

A tree is a hierarchical structure composed of nodes connected by directed edges. The single entry node is the root. Each node may reference child nodes; nodes with no children are leaves. A binary tree restricts each node to at most two children, conventionally designated left and right.

Definition: root, child, leaf, BST, hash table
  • Root — the initial node from which all others descend. Child — a node directly below another. Leaf — a node with no children.
  • BST (Binary Search Tree) — a binary tree satisfying the ordering invariant: all values in the left subtree are less than the node, all values in the right subtree are greater. This invariant permits O(log n) search when the tree is balanced.
  • Balanced — depth is logarithmic in node count rather than degenerating into a linear chain. std::map maintains balance internally.
  • Hash table — a structure in which a hash function maps each key to a bucket index. Average lookup is O(1), but iteration order is unspecified. This is std::unordered_map.

BST with 5 at the root, 3 left, 8 right:

      5
      / \
     3   8
    / \
   1   4

Invariant: left < parent < right
- 3 < 5, so 3 is left of 5
- 8 > 5, so 8 is right of 5
- 1 < 3, so 1 is left of 3
#include <map>          // ordered map: balanced BST, O(log n), ordered keys
#include <unordered_map> // hash table: average O(1), unordered keys
#include <iostream>
#include <string>

// Binary tree node for instruction:
struct Tree {
    int val;
    Tree* l; // left child (lesser values in a BST)
    Tree* r; // greater values in a BST)
    Tree(int v): val(v), l(nullptr), r(nullptr) {}
};

// Inorder traversal: left -> node -> right.
// For a BST this visits values in ascending order.
void inorder(Tree* t) {
    if (t == nullptr) return; // empty subtree: nothing to visit
    inorder(t->l);             // 1. visit lesser values
    std::cout << t->val << " "; // 2. visit current node
    inorder(t->r);             // 3. visit greater values
}

int main() {
    // std::map maintains keys in order (tree-based):
    std::map<std::string, int> age;
    age["bob"] = 25;
    age["alice"] = 30; // iterates alice before bob (ordered)
    for (auto& p : age) std::cout << p.first << " " << p.second << "\n";

    // std::unordered_map provides faster average lookup, unordered (hash-based):
    std::unordered_map<std::string, int> score;
    score["alice"] = 100; // hash("alice") determines the bucket holding 100
    std::cout << score["alice"] << "\n";

    // Manually constructed BST:    5
    //                             / \
    //                            3   8
    Tree* root = new Tree(5);
    root->l = new Tree(3);
    root->r = new Tree(8);
    inorder(root); // prints "3 5 8" — ascending order
    std::cout << "\n";
    // (release allocations in production code; omitted for brevity)
    return 0;
}

Traversal orders

Definition: traversal, DFS, BFS
Traversal visits every node exactly once. DFS (Depth-First Search) descends each path fully before visiting siblings (implemented with recursion or an explicit stack). BFS (Breadth-First Search) visits nodes level by level (implemented with a queue).
  • Inorder (L → Node → R): ascending order for a BST; suitable for ordered output.
  • Preorder (Node → L → R): suitable for copying or serializing structure.
  • Postorder (L → R → Node): suitable for safe deallocation (children before parent) and bottom-up aggregation.
  • BFS with queue: shortest path in unweighted graphs; level-order processing.

Inorder3, 5, 8Ordered output from a BST

Postorder3, 8, 5Deallocate or aggregate children before parent

Map selection: When ordered iteration or range queries are required (“all keys A–M”), use std::map (tree, O(log n)). When maximum average lookup speed is required and order is irrelevant (caches, frequency counts), use std::unordered_map (hash, average O(1)).

6. Recursion: functions that call themselves

Recursion defines a problem in terms of a smaller instance of itself. A recursive function contains a base case that returns directly and a recursive case that invokes the function on reduced input and combines the result.

Definition: base case, recursive case, call stack, memoization
  • Base case — the minimal input with a direct result and no further self-invocation. Without it, recursion does not terminate and exhausts the call stack (stack overflow).
  • Recursive case — reduction plus combination. Example: fact(5) = 5 × fact(4).
  • Call stack — the sequence of pending invocations awaiting return. Each recursive call adds a frame; the base case initiates unwinding.
  • Memoization — caching computed results in an auxiliary array (memo) so each distinct subproblem is solved once, reducing exponential cost to linear.
#include <vector>
#include <iostream>

// Factorial: 5! = 5*4*3*2*1 = 120
// Base: fact(0) and fact(1) are 1 by definition; recursion stops here.
int fact(int n) {
    if (n <= 1) return 1;  // BASE CASE: minimal input, direct result
    return n * fact(n - 1);   // RECURSIVE CASE: n combined with solution of reduced input
}
// fact(3) expands as: 3*fact(2) -> 3*2*fact(1) -> 3*2*1 = 6

// Fibonacci: 0,1,1,2,3,5,8... each term is the sum of the preceding two.
// Unoptimized version: two self-invocations recompute identical subproblems.
int fib(int n) {
    if (n <= 1) return n; // BASE: fib(0)=0, fib(1)=1
    return fib(n - 1) + fib(n - 2); // two reduced subproblems
}
// fib(5) invokes fib(4)+fib(3); fib(3) is then computed twice.
// Complexity is O(2^n) — exponential: fib(50) is computationally infeasible.

// Optimized version with memoization:
// m[i] holds fib(i), or -1 when not yet computed.
int fibMemo(int n, std::vector<int>& m) {
    if (n <= 1) return n; // BASE CASE evaluated first
    if (m[n] != -1) return m[n]; // cached result: return without recomputation
    // Compute once, store, then return:
    return m[n] = fibMemo(n - 1, m) + fibMemo(n - 2, m);
}

int main() {
    std::cout << fact(5) << "\n"; // 120
    std::cout << fib(10) << "\n";  // 55 (unoptimized version acceptable only for small n)

    int n = 40;
    std::vector<int> memo(n + 1, -1); // cache of size n+1, all entries marked unknown (-1)
    std::cout << fibMemo(n, memo) << "\n"; // efficient even for 40
    return 0;
}
CodeBehavior
if (n <= 1) return ...Base-case guard — evaluated first. It terminates recursion. Omission produces unbounded self-invocation and termination failure.
return n * fact(n-1);Recursive case: assumes fact(n-1) is correct and scales it by n. Each caller remains on the call stack until the reduced result returns.
fib(n-1)+fib(n-2)Two self-invocations per call produce exponential branching. A call tree for fib(5) contains fib(3) twice and fib(2) three times — redundant computation.
if (m[n]!=-1) return m[n];Cache lookup: if fib(n) was previously solved, return it in O(1), eliminating the repeated subtree.
return m[n] = ...Single computation followed by storage and return. Subsequent calls for the same n are constant time. Total complexity O(n) instead of O(2ⁿ).
Recursion checklist: 1) Define the base case. 2) Ensure each recursive call reduces the input. 3) Confirm all paths reach the base case. Validate with minimal inputs (0, 1, 2) and trace invocations when behavior is unclear. A crash or hang typically indicates a missing or unreachable base case.
