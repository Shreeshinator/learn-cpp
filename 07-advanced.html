Templates, exceptions, lambdas, threads, filesystem & system calls

These facilities support production-scale C++: generic code, structured error handling, inline callables, concurrency, filesystem access, and interaction with the operating system. Each term is defined on first use, followed by a complete example and a line-by-line walkthrough.

1. Templates — generic code parameterized by type

A function such as int biggest(int a, int b) applies only to int. Duplicating it for double or string repeats identical logic for each type.

A template defines logic once with a type parameter. The compiler instantiates a type-specific version for each type used at a call site. One definition therefore serves int, double, string, and other compatible types.

Definition: template, type parameter, compile-time instantiation
  • Template — a definition parameterized by type, e.g. “maximum of two values of type T”. T is a placeholder resolved per use.
  • typename (or class) in template<typename T> declares that T is a type parameter. In this context it does not denote an OOP class.
  • Compile-time instantiation — resolution during the build. Calls to myMax(3,7) and myMax(3.5,2.1) cause the compiler to generate int and double specializations respectively.
  • Class template — the same mechanism applied to a class, e.g. Box<T> or std::vector<T>. vector itself is a class template, which is why vector<int> and vector<string> are both valid.
#include <iostream>
#include <string>
#include <vector>

// Function template: maximum of two values of identical type T.
// T is deduced from the arguments: int, double, string...
template<typename T>
T myMax(T a, T b) {
    return (a > b) ? a : b; // ternary: evaluates to a if a>b, else b
}

// Class template: a container holding a single value of type T.
template<typename T>
class Box {
    T v; // stored value of type T
public:
    Box(T x): v(x) {}      // constructor initializes v from x
    T get() const { return v; } // returns the stored value
};

int main() {
    // int arguments -> compiler instantiates myMax<int>:
    std::cout << myMax(3, 7) << " ";         // 7
    // double arguments -> compiler instantiates myMax<double>:
    std::cout << myMax(3.5, 2.1) << "\n";   // 3.5
    // string arguments -> compiler instantiates myMax<string>:
    std::cout << myMax(std::string("apple"), std::string("banana")) << "\n";

    Box<std::string> b("hi"); // Box instantiated for std::string
    std::cout << b.get() << "\n"; // hi

    Box<int> bi(42); // identical definition instantiated for int
    std::cout << bi.get() << "\n"; // 42
    return 0;
}
LineExplanation
template<typename T>Declares T as a type parameter. The following function or class applies to any T.
T myMax(T a, T b)Accepts two values of type T and returns type T. T is bound per call site.
return (a>b)?a:b;Returns the greater operand. Requires that T supports operator>; int, double, and string satisfy this.
class Box { T v; ... }Defines storage for one value of type T. Structure is fixed; the value type varies per instantiation.
Box<std::string> b("hi");Instantiates the class with T fixed to string for this object.
Selection rule: Use a template when the logic is identical and only the type varies (maximum, exchange, output, containers). When behavior differs per type, prefer overloads or separate definitions.

2. Exceptions — structured propagation of runtime errors

Standard execution follows the expected path: division succeeds, files open. When an operation cannot produce a valid result — division by zero, missing file — the function must signal failure to the caller. C++ provides throw to raise an error object, try to delimit code that may raise, and catch to handle the error at a suitable level.

Definition: exception, throw, try, catch, what()
  • Exception — an error object that transfers control to a handler, e.g. std::runtime_error("divide by zero").
  • throw — raises an exception: throw std::runtime_error(...). The function exits immediately; no further statements execute.
  • try — designates a block that may raise. Code that can throw is placed inside try { ... }.
  • catch — handles a raised exception. catch(const std::exception& e) accepts most standard errors. e.what() returns the diagnostic message.
  • Stack unwinding — after a throw, active function calls terminate in reverse order until a matching catch is found. If none exists, the program terminates.
#include <stdexcept> // for std::runtime_error, std::exception
#include <iostream>

// When b is zero no quotient exists — raise instead of returning a sentinel.
double divide(double a, double b) {
    if (b == 0) {
        throw std::runtime_error("divide by zero"); // raise error object
    }
    return a / b; // standard path: defined division
}

int main() {
    // Delimit operations that may raise:
    try {
        std::cout << divide(10, 2) << "\n"; // 5 — no exception, standard output
        std::cout << divide(1, 0) << "\n";  // throws — control transfers to catch
        std::cout << "you never see this\n";    // unreachable after throw
    }
    catch (const std::exception& e) {
        // Handler: report the condition and continue defined execution.
        std::cout << "Error: " << e.what() << "\n"; // Error: divide by zero
    }
    std::cout << "program continues safely\n";
    return 0;
}
LineExplanation
throw std::runtime_error(...)Constructs an error object with a message and exits divide() immediately; the subsequent return does not execute.
try { ... }Marks the enclosed statements as exception-aware. Execution proceeds sequentially until a throw occurs.
Statement after throw is skippedControl leaves the try block at the throw point; remaining statements in the block do not execute.
catch(const std::exception& e)Receives the thrown object. The reference (&) avoids a copy; const prohibits modification.
e.what()Returns the stored message: "divide by zero".
Exceptions vs. return values: Use exceptions for unexpected failure conditions (resource exhaustion, missing required file, invalid domain such as division by zero). For routine outcomes such as invalid user input or absent search results, prefer return codes or std::optional. Never suppress an exception with an empty catch block; at minimum record the diagnostic.

3. Lambdas — anonymous functions defined inline

A named function is declared separately from its call site. When a short predicate or comparator is required exactly once — for filtering, counting, or ordering — a separate named definition adds indirection. A lambda defines an anonymous function at the point of use.

Definition: lambda, capture, parameters, body
A lambda has the form [capture](parameters){ body }:
  • [capture] — variables from the enclosing scope made visible inside the lambda. [] captures nothing. [&] captures by reference. [=] captures by copy. [threshold] copies only threshold. [&threshold] references only threshold.
  • (parameters) — inputs, as in a standard function. Example: (int x).
  • { body } — implementation. Must yield a value convertible to the type required by the algorithm (e.g. bool for count_if or a strict ordering for sort).
  • Reference (&) vs. copy (=): a reference observes and can modify the original; a copy operates on a snapshot. Prefer copies unless shared mutable access is required.
#include <vector>
#include <algorithm> // count_if, sort
#include <iostream>

int main() {
    std::vector<int> v = {1, 2, 3, 4, 5};
    int threshold = 3;

    // Count elements exceeding 3.
    // For each x in v, the predicate evaluates x > threshold.
    // [&] grants access to enclosing variables by reference.
    int n = std::count_if(v.begin(), v.end(),
        [&](int x) { return x > threshold; });
    std::cout << n << "\n"; // 2 (elements 4 and 5)

    // Equivalent with explicit capture restricted to threshold:
    // [&](int x){...} vs [&threshold](int x){...} — the latter is more precise.

    // Order descending: a precedes b when a > b.
    // [] indicates no external state is required, only a and b.
    std::sort(v.begin(), v.end(),
        [](int a, int b) { return a > b; });
    // v is now 5 4 3 2 1

    for (int x : v) std::cout << x << " ";
    std::cout << "\n";
    return 0;
}
Lambda componentExplanation
[&]Captures enclosing variables by reference. The lambda observes the current value of threshold.
[]Captures nothing. Appropriate when the operation depends only on its parameters.
(int x) / (int a, int b)Parameters. count_if supplies each element as x; sort supplies pairs (a,b) and interprets a true result as “a precedes b”.
{ return x > threshold; }Predicate body. count_if counts elements for which it returns true.
Usage rule: When a callable is used once and spans one to three lines, define it as a lambda at the call site. When it is reused across call sites or exceeds that scope, define a named function so it can be documented and tested independently.

4. Threads and mutexes — concurrent execution with synchronized access

Sequential execution performs one statement at a time. A thread is an independent execution path; multiple threads execute concurrently within one process. Concurrency reduces elapsed time for parallelizable work but introduces shared-state hazards when threads access the same object without coordination.

Definition: thread, shared data, data race, mutex, lock_guard, join
  • Thread (std::thread) — an independent execution path. main() executes on the initial thread; emplace_back(work,i) starts an additional thread executing work(i).
  • Shared data — any object accessible from multiple threads, e.g. std::cout or a counter.
  • Data race — concurrent unsynchronized modification of shared data, where the result depends on scheduling. In C++ this is undefined behavior: the standard imposes no defined outcome.
  • Mutex (std::mutex, mutual exclusion) — a synchronization primitive permitting exactly one holder at a time. Threads without the mutex block until it is available.
  • lock_guard — an RAII guard that acquires on construction and releases on destruction (including exception paths). Explicit unlock is unnecessary.
  • join() — blocks until the associated thread completes. Without it, main may terminate while worker threads are still active.
#include <thread>   // std::thread, std::this_thread
#include <vector>
#include <iostream>
#include <mutex>    // std::mutex, std::lock_guard

std::mutex m; // single mutex protecting shared output

// Each thread executes this function with a distinct id.
void work(int id) {
    // Acquire exclusive access for the extent of this block.
    // Exactly one thread holds the mutex within these braces at a time.
    std::lock_guard<std::mutex> lock(m); // acquisition point
    std::cout << "thread " << id << "\n";
} // release point (guard destroyed)

int main() {
    std::vector<std::thread> ts; // active threads

    for (int i = 0; i < 4; i++) {
        ts.emplace_back(work, i); // start thread executing work(i) concurrently
    }
    for (auto& t : ts) {
        t.join(); // block until each thread completes before exiting main
    }
    return 0;
}
// Compile: g++ -std=c++17 prog.cpp -pthread -o prog
// -pthread enables thread support.
LineExplanation
std::mutex m;Defines one mutex shared by all threads. Global scope ensures a single instance.
std::lock_guard<std::mutex> lock(m);Acquires the mutex on construction. A thread arriving while another holds it blocks. Release is automatic at scope exit, including exception paths.
std::cout << ... inside lockRestricts shared output to the mutex holder. Without synchronization, characters from concurrent threads interleave.
ts.emplace_back(work,i);Constructs and starts a thread executing work(i). Execution proceeds concurrently.
t.join();Waits for the thread to complete. Joining all threads ensures all work is finished before exit.
Synchronization rule: shared mutable data accessed from multiple threads requires a mutex or atomic. Restrict the locked region (critical section) to the shared access, not the surrounding computation. Acquiring multiple mutexes in inconsistent orders across threads risks deadlock. For a simple counter, std::atomic<int> is preferable to a mutex.

5. Filesystem — portable file and directory operations

std::filesystem (C++17) provides portable operations for enumerating directories, testing entry types, creating directories, and querying file attributes across Windows, macOS, and Linux without OS-specific calls.

Definition: filesystem, path, directory, iterator
  • std::filesystem — standard facility for files and directories. Requires C++17 (-std=c++17).
  • path (p.path()) — filesystem address of an entry, e.g. "demo/a/b" or "./notes.txt".
  • Directory — container for entries. File — data entry within a directory.
  • directory_iterator(".") — enumerates entries in one directory. recursive_directory_iterator — enumerates entries including nested subdirectories.
  • Namespace alias namespace fs = std::filesystem; abbreviates qualified names: fs::path for std::filesystem::path.
#include <filesystem> // portable file and directory operations
#include <iostream>

namespace fs = std::filesystem; // alias permitting fs:: prefix

int main() {
    // 1. Enumerate entries in the current directory ("." denotes current).
    // p is each entry (file or directory) yielded in sequence.
    for (auto& p : fs::directory_iterator(".")) {
        std::cout << p.path() << " "
                  << (fs::is_directory(p) ? "[dir]" : "[file]")
                  << "\n";
    }

    // 2. Create nested directories demo/a/b (including missing parents).
    fs::create_directories("demo/a/b");

    // 3. Query file size in bytes.
    // The target must exist; otherwise a filesystem_error is thrown.
    std::cout << fs::file_size("07-advanced.html") << " bytes\n";

    // 4. Recursive variant enumerating all descendants:
    // for (auto& p : fs::recursive_directory_iterator(".")) { ... }
    return 0;
}
// Compile: g++ -std=c++17 prog.cpp -o prog
// (Current toolchains link filesystem automatically.)
LineExplanation
fs::directory_iterator(".")Enumerates entries in the current directory.
p.path()Returns the entry address, e.g. "./demo".
fs::is_directory(p) ? "[dir]" : "[file]"Tests the entry type and selects the corresponding label.
fs::create_directories("demo/a/b")Creates the full path including missing parents. Idempotent — no effect if the path exists.
fs::file_size(...)Returns the size in bytes. Throws if the file is absent — handle with try/catch in production code.

6. System calls — controlled requests to the kernel

Application code executes with restricted privileges and cannot directly control hardware or other processes. The kernel (the privileged OS core) mediates such operations. A system call is a formal request to the kernel — open a file, start a process, suspend for a duration. C++ standard facilities wrap the most common requests portably; direct OS interfaces are reserved for cases the standard does not cover.

Definition: kernel, system call, POSIX, Windows API, portable
  • Kernel — privileged OS core managing hardware and isolation. Application code runs in user mode; the kernel runs in privileged mode.
  • System call — invocation by which user code requests a privileged kernel operation (file access, process creation, socket setup).
  • POSIX — the Linux/macOS interface family (e.g. fork(), execvp(), opendir()).
  • Windows API — the Windows interface family (e.g. CreateProcess(), FindFirstFile(), Sleep()).
  • Portable — valid across platforms. Prefer std::filesystem, std::thread, and std::chrono over direct OS calls except where OS-specific behavior is the subject (e.g. Lesson 10).
OperationPOSIX (Linux / macOS)WindowsPortable C++ (preferred)
Run another programfork() + execvp() — duplicate the process, then replace the copy with the target programCreateProcess()No single standard facility; see shell lesson (Lesson 10). Provisional option: std::system() below
List filesopendir() / readdir()FindFirstFile() / FindNextFile()std::filesystem::directory_iterator
Network socketsocket() / bind() / listen()Winsock2 (WSAStartup first)Library such as Asio, or #ifdef per OS
Sleep / measure timesleep() / usleep()Sleep() (milliseconds, capital S)std::this_thread::sleep_for() + std::chrono
Definition: fork/exec vs. CreateProcess; directory enumeration APIs
  • fork() duplicates the calling process. execvp() replaces the duplicate with the specified program. POSIX program launch uses both steps.
  • CreateProcess() starts a new process in a single call on Windows. The observable effect matches fork/exec with a different interface.
  • opendir/readdir and FindFirstFile both expose directory enumeration as “open a directory, read names sequentially”. std::filesystem abstracts this difference and is therefore preferred.
#include <thread>   // for sleep_for
#include <chrono>   // for clocks and durations
#include <cstdlib>  // for std::system
#include <iostream>

int main() {
    // --- Portable interval measurement and suspension ---
    // steady_clock is monotonic and never adjusts backward,
    // unlike wall-clock time. It is appropriate for elapsed-time measurement.
    auto t0 = std::chrono::steady_clock::now();

    // Suspend this thread for 500 ms. The OS deschedules the thread
    // and resumes it after the interval — no polling, no CPU consumption.
    std::this_thread::sleep_for(std::chrono::milliseconds(500));

    auto t1 = std::chrono::steady_clock::now();
    // Convert the interval to milliseconds for output:
    auto ms = std::chrono::duration_cast<std::chrono::milliseconds>(t1 - t0);
    std::cout << "slept " << ms.count() << " ms\n";

    // --- Execute an external command through the OS shell ---
    // system() submits the string to the platform shell (cmd on Windows,
    // sh on Linux/macOS) and returns the exit code (conventionally 0 = success).
    int rc = std::system("echo hello from OS");
    std::cout << "exit code " << rc << "\n";
    // Caution: system() delegates to the shell — never forward unsanitized
    // user input (command-injection risk). For a controlled shell, use fork/exec
    // or CreateProcess directly (Lesson 10).
    return 0;
}
LineExplanation
steady_clock::now()Records a timestamp. Two timestamps delimit an interval. Monotonic behavior ensures validity even if the system clock is adjusted.
sleep_for(milliseconds(500))Requests suspension for 500 ms. The OS schedules other work during the interval.
duration_cast<...>(t1-t0)Converts the interval to milliseconds. .count() yields the numeric value.
std::system("echo ...")Delegates the command to the OS shell and returns its exit code. Convenient for scripts; unsuitable for untrusted input.

7. Splitting projects + CMake: multi-file builds

Single-file programs do not scale. Production code separates interface from implementation: a header file (.h) declares available entities, and a source file (.cpp) defines them. main.cpp consumes the declarations. A minimal build description (CMake) specifies which translation units compose the executable.

Definition: declaration vs. definition, header, #pragma once, CMake
  • Declaration — a specification: “int add(int a,int b); exists” (terminated, no body). Definition — the implementation: “int add(...) { return a+b; }”.
  • Header (.h) — declarations imported with #include "math.h". Source (.cpp) — corresponding definitions. Quoted form "..." denotes a project-local file; bracket form <...> denotes a system or library header.
  • #pragma once — restricts inclusion to once per translation unit, preventing duplicate-definition errors from repeated inclusion.
  • CMake — a build generator. A short CMakeLists.txt (“build executable app from these sources”) produces platform-specific build commands.
// ---- File: math.h (declarations) ----
#pragma once // include at most once per translation unit
int add(int a, int b); // declaration: add accepts two ints and returns int

// ---- File: math.cpp (definitions) ----
#include "math.h" // verify definitions against declarations
int add(int a, int b) { return a + b; } // definition: implementation

// ---- File: main.cpp (use) ----
#include <iostream> // system facility: input/output
#include "math.h"     // project declarations: authorizes calls to add()
int main() {
    std::cout << add(2, 3) << "\n"; // 5
    return 0;
}

// ---- Build without CMake (direct g++): ----
// g++ -std=c++17 main.cpp math.cpp -o app
// Meaning: compile both translation units and link into program "app".
// Omitting math.cpp yields "undefined reference to add" (declaration without definition).

// ---- File: CMakeLists.txt (build description) ----
// cmake_minimum_required(VERSION 3.15) // minimum required CMake version
// project(myapp)                       // project name
// add_executable(app main.cpp math.cpp) // executable app composed of these sources
// Build with:
// cmake -S . -B build   (process description, prepare build/ directory)
// cmake --build build   (compile and link)
LineExplanation
#pragma oncePrevents multiple inclusion of the header within one translation unit, avoiding redefinition errors.
int add(int a,int b); in .hDeclaration: signature and return type without implementation.
#include "math.h" in math.cppAligns the definition with its declaration; the compiler diagnoses mismatches.
#include "math.h" in main.cppIntroduces the declaration so add() can be called and type-checked.
g++ main.cpp math.cpp -o appCompiles both sources and links them into app. Linking resolves declarations to definitions.
add_executable(app main.cpp math.cpp)CMake equivalent: defines executable target “app” from the two sources.
Structural model: Header specifies the interface (available functions and types). Source file implements it. The consuming translation unit references the header. The linker binds references to implementations. CMake records this composition for repeatable builds.

✅ Exercises

  1. Generic printer: Write a function template printVector accepting const std::vector<T>& v and emitting each element separated by spaces. Instantiate it with vector<int> {1,2,3} and vector<string> {"hi","bye"}. One definition must serve both types.
  2. Observe and correct a data race: Define int counter = 0; and launch two threads each executing for (int i=0;i<100000;i++) counter++;. Without synchronization the result is typically below 200000 (lost updates). Then protect counter++ with std::mutex + lock_guard (or replace with std::atomic<int>) and confirm 200000 on every run.
  3. Directory inventory: With fs::recursive_directory_iterator("."), enumerate all files under the current directory, output each path with file_size (guarded by try/catch for inaccessible entries), and accumulate the total in long long total.
  4. Minimal CMake project: Create a directory containing math.h, math.cpp (add and multiply), main.cpp (invokes both), and CMakeLists.txt with the three directives above. Configure with cmake -S . -B build, build with cmake --build build, and run the result. Remove math.cpp from the target once to inspect the linker diagnostic, then restore it.
  5. Lambda facility: Given vector<int> v = {5,1,4,2,3}, apply count_if with a lambda to count even elements (x % 2 == 0), then sort with a lambda for ascending order. Compare captures [&] and [] and state why each is or is not sufficient.
Completion criteria: You can define templates and their instantiation point, handle errors with try/catch, decompose a lambda into capture, parameters, and body, explain thread synchronization with mutexes, and partition a single-file program into headers, sources, and a CMake build.
