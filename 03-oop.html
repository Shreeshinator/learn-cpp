Object-Oriented Programming: Classes, Inheritance, Polymorphism

This lesson covers object-oriented programming in C++: classes and objects, access control, encapsulation, constructors and destructors, inheritance, virtual dispatch, abstraction, object lifetime rules, and composition. Each term is defined on first use, followed by complete, annotated examples.

1. What is OOP? Why does it exist?

Without encapsulation, related state and operations are stored in separate variables and free functions with unrestricted access:

string player1Name = "Asha";
int player1Hp = 80;
string player2Name = "Ravi";
int player2Hp = 90;
// ... 50 more players ...
void healPlayer1(int n) { player1Hp += n; }
// ... 200 lines later, which function modified player1Hp, and is the value valid?

At small scale this is manageable. At larger scale, unrestricted access to shared state makes it difficult to determine where a value was modified and whether invariants hold. OOP addresses this by grouping related data and the operations permitted on that data into a single type.

Definition — function
A named, callable unit that accepts zero or more arguments, executes a sequence of statements, and optionally returns a value.
Definition — global variable
A variable with program-wide scope. It is accessible from any function, which makes unintended modification difficult to trace.
Definition — OOP (Object-Oriented Programming)
A design approach in which data (member variables) and the operations on that data (member functions) are defined together in a class. An object is an instance of a class. Access control restricts which code can modify internal state.

OOP is conventionally described by four properties:

PropertyDefinitionExample
EncapsulationInternal state is private; modification is permitted only through a defined public interface that enforces invariants.BankAccount::withdraw() rejects withdrawals exceeding the balance.
InheritanceA derived class reuses and extends the interface and implementation of a base class.Dog derives from Animal and reuses name.
PolymorphismThe same interface produces type-specific behavior. Pronounced pol-ee-MOR-fiz-um.Animal::speak() executes Dog::speak() or Cat::speak() depending on the dynamic type.
AbstractionClients depend on an interface (what operations exist), not on implementation details (how they execute).Calling shape.area() without knowledge of the concrete shape type.

2. What is a class? What is an object?

Definition — class
A user-defined type that specifies a set of member variables and member functions. A class defines data and operations. It specifies structure and behavior but holds no per-instance storage until instantiated.
Definition — object
An instance of a class: a concrete entity with its own storage for each non-static member variable. Multiple objects of the same class share the same interface but maintain independent state.
Definition — member
An element declared inside a class. A member variable (field) stores per-object or shared state. A member function (method) operates on objects of that class.
#include <iostream>
#include <string>

struct Player {
    std::string name;
    int hp = 100;
    void heal(int n){ hp += n; }
};

int main(){
    Player p{"Asha", 80};
    p.heal(10);
    std::cout << p.name << " " << p.hp << "\n"; // prints: Asha 90
}

Line-by-line explanation:

LineDescription
#include <iostream>Declares standard output facilities, including std::cout.
#include <string>Declares std::string for owning character sequences.
struct Player { ... };Defines a class type named Player. The trailing ; terminates the class definition.
std::string name;Declares a per-object member variable storing the player name.
int hp = 100;Declares a per-object member variable with default member initializer 100.
void heal(int n){ hp += n; }Declares a member function that adds n to the hp of the object on which it is called. void indicates no return value.
Player p{"Asha", 80};Defines object p of type Player, initialized with name="Asha" and hp=80.
p.heal(10);Invokes heal on p. Only p.hp is modified. The . operator selects a member of an object.
std::cout << p.name ...Inserts p.name and p.hp into the output stream. << is the stream insertion operator.

3. struct vs class

Definition — struct and class
Both declare class types with identical capabilities (member functions, constructors, inheritance). The sole difference is the default member access: struct members are public by default; class members are private by default. Explicit access specifiers override the default in either case.
Propertystructclass
Default member accesspublicprivate
Typical usePassive data aggregates without invariants, e.g., Point{x, y}Types that enforce invariants, e.g., BankAccount
Supported featuresMember functions, constructors, inheritance — full supportMember functions, constructors, inheritance — full support
struct Point { double x, y; }; // Point p; p.x = 5; is valid

class BankAccount {
    double balance = 0; // private by default; inaccessible from outside
};
Guideline: use struct for data without constraints. Use class when the type must maintain an invariant, such as a non-negative balance.

4. public, private, protected

Definition — public / private / protected
Access specifiers controlling which code may use a member. public: accessible to all code. private: accessible only to member functions (and friends) of the same class. protected: accessible to the class and its derived classes, but not to external code.
class Account {
public:
    void deposit(double amt);
private:
    double balance = 0;
protected:
    std::string auditTag = "std";
};
SpecifierAccessible fromUsed for
publicAll code, including main()Validated interface: deposit(), speak()
privateOnly member functions of the same classInternal state: balance
protectedThe class and its derived classesImplementation details shared with derived classes

5. Encapsulation

Definition — encapsulation (en-cap-soo-LAY-shun)
The practice of declaring data members private and exposing only member functions that preserve the type's invariants. All state transitions pass through validated operations.

Encapsulation exists to maintain the invariant.

Definition — invariant
A condition that must hold for the entire lifetime of every valid object, e.g., "balance is never negative." Member functions are required to preserve it.

6. Constructors and destructors

Definition — constructor
A special member function invoked automatically at object creation. It establishes a valid initial state. It has the same name as the class and no return type, including no void.
Definition — destructor
A special member function invoked automatically at object destruction (end of scope or delete). Its name is the class name prefixed with ~, e.g., ~BankAccount(). It releases resources acquired by the object.
Definition — initializer list
The : balance(initial) clause in a constructor definition. It directly initializes members before the constructor body executes. It is more efficient than assignment and is required for references, const members, and members without default constructors.
class BankAccount {
    double balance = 0;
public:
    BankAccount(double initial) : balance(0) {
        if (initial >= 0) balance = initial;
    }
    ~BankAccount() { /* release resources here */ }
};

Constructor categories:

CategoryDeclarationInvocation
DefaultBankAccount();BankAccount a;
ParameterizedBankAccount(double initial);BankAccount a(500);
CopyBankAccount(const BankAccount& other);BankAccount b = a;
MoveBankAccount(BankAccount&& other);Transfer from an expiring value (see Lesson 04)
Definition — const member function
double getBalance() const { ... } — the trailing const specifies that the function does not modify the object. It may be called on const objects, and the compiler rejects any modification within it.

7. Full example 1: BankAccount

#include <iostream>
#include <string>

class BankAccount {
private:
    double balance = 0;
public:
    BankAccount(double initial) { if(initial >= 0) balance = initial; }
    void deposit(double amt){ if(amt > 0) balance += amt; }
    bool withdraw(double amt){
        if(amt > 0 && amt <= balance){ balance -= amt; return true; }
        return false;
    }
    double getBalance() const { return balance; }
};

int main(){
    BankAccount a(500);
    a.deposit(200);
    a.withdraw(100);
    std::cout << a.getBalance() << "\n"; // prints 600
    // a.balance = 99999; // ERROR — private access violation
}
LineDescription
class BankAccount {Begins the definition of class type BankAccount.
private: double balance = 0;Declares private storage for the balance, default-initialized to 0. External code cannot name this member.
BankAccount(double initial)...Constructor establishing the invariant: a negative initial value is rejected and the balance remains 0.
void deposit(double amt)...Public operation that increases the balance only for positive amounts.
bool withdraw...Public operation that decreases the balance only if amt is positive and does not exceed the balance. Returns true on success, false otherwise.
double getBalance() constConst accessor returning the current balance without modifying the object.
BankAccount a(500);Defines object a; the constructor sets the balance to 500.
a.balance = 99999; (commented)Ill-formed: the compiler rejects direct access to a private member. The rejection confirms encapsulation.
Professional practice: declarations are placed in a header (BankAccount.h) and definitions in a source file (BankAccount.cpp). A single file is sufficient for introductory examples.

8. Inheritance and the is-a relationship

Definition — inheritance
A mechanism by which a derived class acquires the members of a base class and may add or override behavior. The base class is also termed parent or superclass; the derived class is also termed child or subclass. Syntax: class Dog : public Animal.
Definition — is-a test
A validity criterion for public inheritance: inheritance is appropriate only if every derived object is logically a base object. A Dog is an Animal, so derivation is valid. A Game is not a Player, so a Game should contain a Player (composition) rather than derive from it.
#include <iostream>
#include <string>

class Animal {
public:
    std::string name;
    Animal(std::string n):name(n){}
    virtual void speak() const { std::cout << name << " makes a sound\n"; }
    virtual ~Animal() = default;
};
class Dog : public Animal {
public:
    Dog(std::string n):Animal(n){}
    void speak() const override { std::cout << name << " barks!\n"; }
};
class Cat : public Animal {
public:
    Cat(std::string n):Animal(n){}
    void speak() const override { std::cout << name << " meows!\n"; }
};
LineDescription
class Animal { ... };Base class defining state and operations common to all animals.
Animal(std::string n):name(n){}Constructor directly initializing member name from parameter n.
virtual void speak() constDeclares a virtual function that derived classes may override. Dispatch is resolved at runtime.
virtual ~Animal() = default;Virtual destructor ensuring destruction through a base pointer invokes the derived destructor. = default requests the compiler-generated implementation. A non-virtual destructor in a polymorphic base is a defect.
class Dog : public AnimalDerives Dog from Animal. Public inheritance models the is-a relationship.
Dog(std::string n):Animal(n){}Derived constructor forwarding n to the base constructor before executing the derived body.
void speak() const overrideOverrides the base implementation. override requires the compiler to verify a matching base virtual exists, which detects signature errors.

9. virtual, override, and the vtable

Definition — virtual function
A member function declared virtual in the base class. Calls through a pointer or reference are dispatched to the override corresponding to the dynamic (runtime) type of the object.
Definition — override
A specifier on a derived declaration indicating intent to override a base virtual. It adds no dispatch behavior; it enforces correctness by requiring a matching base declaration.
Definition — vtable (virtual table)
A per-class table generated by the compiler mapping each virtual function to its concrete implementation. Each polymorphic object holds a pointer to its class's vtable, enabling runtime selection of the correct override through a base pointer.
#include <memory>
#include <vector>
int main(){
    std::vector<std::unique_ptr<Animal>> zoo;
    zoo.push_back(std::make_unique<Dog>("Rex"));
    zoo.push_back(std::make_unique<Cat>("Mimi"));
    for(auto& a: zoo) a->speak();
}
LineDescription
vector<unique_ptr<Animal>> zoo;Declares a dynamic array of exclusive-ownership pointers to Animal. Each element may point to any derived type.
make_unique<Dog>("Rex")Allocates a Dog object and returns a unique_ptr managing it. Ownership transfer requires no explicit delete.
a->speak()Invokes speak through the pointer. -> dereferences the pointer and selects the member. Virtual dispatch selects Dog::speak or Cat::speak per element.
Omitting virtual: a->speak() resolves statically to Animal::speak for all elements, because selection is based on the static pointer type rather than the dynamic object type.

10. Polymorphism — compile-time vs runtime

Definition — polymorphism ("many forms")
The use of a single interface to produce behavior specific to the argument types or the dynamic object type. Two categories:
CategoryDesignationResolutionExample
Identical name, distinct parameter typesCompile-time (overloading, templates)Selected by the compiler from the call argumentsprint(5) vs print("hi"); myMax(3,7) vs myMax(2.5,1.1)
Identical call, distinct dynamic typeRuntime (virtual + override)Selected at execution via the vtablea->speak() executes Dog::speak or Cat::speak
Definition — overloading
Declaring multiple functions with the same name but distinct parameter lists, e.g., draw(int x) and draw(int x, int y). The compiler selects the overload from the argument types. No virtual dispatch is involved.
void print(int x) { std::cout << "number " << x << "\n"; }
void print(std::string s) { std::cout << "word " << s << "\n"; }
// print(5) selects the int overload; print("hi") selects the string overload.

11. Pure virtual functions and abstract classes — Full example 3: Shape

Definition — pure virtual function
A virtual function terminated with = 0, e.g., virtual double area() const = 0;. It declares an interface without providing an implementation and requires each concrete derived class to supply an override.
Definition — abstract class
A class containing at least one pure virtual function. It cannot be instantiated directly. Only concrete derived classes that implement all pure virtuals can be instantiated.
class Shape {
public:
    virtual double area() const = 0;
    virtual ~Shape() = default;
};
class Circle : public Shape {
    double r;
public:
    Circle(double radius):r(radius){}
    double area() const override { return 3.14159*r*r; }
};
class Rectangle : public Shape {
    double w, h;
public:
    Rectangle(double width, double height):w(width),h(height){}
    double area() const override { return w*h; }
};
// Shape s; // ERROR — abstract class cannot be instantiated
// Circle c(2.0); // valid — concrete class
LineDescription
virtual double area() const = 0;Pure virtual declaration: derived classes must implement area(). double is the return type; const indicates the call modifies no state.
class Circle : public ShapeDeclares Circle as a derived type subject to the Shape interface contract.
double area() const overrideConcrete implementation satisfying the pure virtual requirement. override enables compiler verification.

12. Rule of 3 / 5 / 0

Definition — Rule of 3 / 5
If a class directly manages a resource (memory from new, a file handle, a socket), the compiler-generated destructor, copy constructor, copy-assignment operator, move constructor, and move-assignment operator are insufficient. A default copy would produce two objects referencing the same resource, resulting in a double release. Such a class must define: destructor, copy constructor, copy-assignment (Rule of 3), plus move constructor and move-assignment (Rule of 5). The preferred alternative is the Rule of 0: hold resources via std::vector, std::string, or unique_ptr, which already implement correct semantics, so no custom special members are required.
class Buffer {
    int* data; int n;
public:
    Buffer(int size): n(size), data(new int[size]{}) {}
    ~Buffer(){ delete[] data; }
    Buffer(const Buffer& o): n(o.n), data(new int[o.n])
    { for(int i=0;i<n;i++) data[i]=o.data[i]; }
    Buffer(Buffer&& o) noexcept: n(o.n), data(o.data)
    { o.data=nullptr; o.n=0; }
};
ConstructDescription
new int[size]{}Allocates an array of size integers with value-initialization (zero-initialized). The pointer stores the address of the first element.
~Buffer(){ delete[] data; }Destructor releasing the array. The [] form is required for arrays. Omission produces a leak.
Buffer(const Buffer& o)Copy constructor performing a deep copy: allocates independent storage and copies each element. const & denotes a read-only reference (no copy of the source).
Buffer(Buffer&& o) noexceptMove constructor transferring ownership: copies the pointer, then sets the source to nullptr so only the new object releases the allocation. && binds to expiring values; noexcept permits efficient use in standard containers.
Rule of 0: if Buffer stored std::vector<int> data; instead of int* data;, all custom special members could be removed. vector implements correct copy, move, and destruction semantics.

13. this, explicit, static, friend, operator overloading

this

Definition — this
An implicit pointer available in every non-static member function, pointing to the object on which the function was called. this->x explicitly refers to the current object's member x. It is required when a parameter shadows a member name, or when the function must return a reference to the object itself.
class Box {
    int w = 0;
public:
    void set(int w){ this->w = w; }
};

explicit

Definition — explicit
A specifier on a single-argument constructor preventing implicit conversion. Without it, Buffer b = 10; would implicitly construct Buffer(10). With it, construction must be direct: Buffer b(10);.
class Buffer2 {
public:
    explicit Buffer2(int n){}
};

static members

Definition — static member
A member with a single instance shared by all objects of the class, rather than per-object storage. A static member function has no this pointer and can access only static data.
class Counter {
public:
    static int total;
    Counter(){ total++; }
};
int Counter::total = 0;
LineDescription
static int total;Declares a shared class-level variable. The declaration does not define storage.
Counter(){ total++; }Constructor incrementing the shared count on each instantiation.
int Counter::total = 0;Defines the static member and initializes it to 0. :: is the scope-resolution operator. This definition appears once in a source file.

friend

Definition — friend
A declaration granting a designated class or function access to private and protected members. Example: friend class B; inside A permits B to access A's non-public members. It weakens encapsulation and should be used selectively.
class A {
    friend class B;
    friend void spy(A&);
private: int x = 1;
};

Operator overloading

Definition — operator overloading
Definition of the behavior of built-in operators (+, ==, <<) for a user-defined type, enabling expressions such as a + b instead of a.add(b).
struct Vec2 {
    double x, y;
    Vec2 operator+(const Vec2& o) const { return {x+o.x, y+o.y}; }
    bool operator==(const Vec2& o) const { return x==o.x && y==o.y; }
};
// Vec2 a{1,2}, b{3,4}; Vec2 c = a + b; // {4,6}. if (a == b) ...
ConstructDescription
operator+Defines a + b for Vec2. The parameter const Vec2& o is a read-only reference avoiding a copy.
const qualifierSpecifies that the operator does not modify either operand.
operator==Defines equality comparison by comparing x and y components. Returns bool.

14. Multiple inheritance, the diamond problem, and composition

Definition — multiple inheritance
Derivation of a class from more than one direct base: class D : public B1, public B2 {}. Permitted in C++ but increases complexity; use only when justified.
Definition — diamond problem
Ambiguity arising when two bases B and C both derive from A, and D derives from both B and C, yielding two A subobjects. Virtual inheritance (class B : public virtual A) produces a single shared A subobject, but avoiding the structure is generally preferable.
class D : public B1, public B2 {};
class B : public virtual A {};
class C : public virtual A {};
class D2 : public B, public C {};
Inheritance formSemanticsRecommendation
public (class Dog : public Animal)Is-a relationship. A Dog can be used wherever an Animal is expected.Standard form for interface hierarchies.
protected / private inheritanceImplemented-in-terms-of. Reuses implementation without establishing substitutability.Rare; composition is generally clearer.
Prefer composition (has-a) to inheritance (is-a). A Game contains a Player; it is not a Player. Deep inheritance hierarchies are fragile because changes propagate to all derived classes. Model shared interfaces with abstract base classes and assemble behavior from member objects.

Exercises

  1. Encapsulated Book. Define class Book with private members title, author, and pages. Provide a constructor, const accessors (getTitle()), and a summary() function printing title, author, and page count. In main(), instantiate one object and call summary().
  2. Polymorphic Shape. Extend the Shape example with Circle and Rectangle implementing area(). In main(), populate vector<unique_ptr<Shape>> with two circles and one rectangle, accumulate the areas in a loop, and print the total.
  3. Person and Student. Define base Person with name and virtual introduce(). Derive Student overriding introduce() to include the school. Invoke introduce() through a Person* to a Student and verify dynamic dispatch selects the derived version.
  4. Operator overloading for Vec2. Define struct Vec2{double x,y;}; with operator+ and operator==. In main(), verify {1,2} + {3,4} == {4,6} and print the result.
  5. Rule of 0. Refactor Buffer to store std::vector<int> instead of int* and remove its destructor, copy, and move members. Verify correct behavior and consider why managed members eliminate manual resource handling.
