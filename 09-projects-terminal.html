Build a terminal app: Todo manager + file organizer

Goal: build two functional command-line tools: a todo manager controlled via arguments (for example todo add "buy milk") and a file organizer that classifies files by extension. This project introduces command-line argument handling, ANSI output formatting, and std::filesystem.

Overview: A terminal application receives input as command-line arguments and produces text output on standard output. Command-line arguments are passed via argc/argv. The filesystem organizer iterates a directory, inspects each file extension, and moves files into categorized subdirectories using std::filesystem operations.

1. CLI and terminal fundamentals

  • Terminal — a text-based interface for executing programs. On Windows this is PowerShell or CMD; on macOS and Linux it is Terminal.
  • CLI (Command Line Interface) — a program operated through typed commands rather than graphical controls. Example: todo list. Contrast with GUI (Graphical User Interface), which uses windows and pointer input.
  • Command — the primary operation specifier. In todo list, list is the command.
  • Argument — additional input data. In todo add "buy milk", add is the command and "buy milk" is an argument. Quotation marks group multiple words into a single argument.
  • Rationale for CLI development: CLI programs require no graphical framework, allowing focus on input parsing, data management, and file I/O. Standard developer tools (git, g++, npm) operate as CLIs.
Summary: The terminal executes programs. A CLI program accepts a command and arguments, performs processing, and writes results to standard output.

2. Command-line arguments: argc and argv

When executing todo add "buy milk", the operating system tokenizes the command line and passes the result to the program. Command-line arguments are passed via argc/argv.

  • int argc — argument count. For todo add "buy milk", argc is 3. For todo list, argc is 2. For todo alone, argc is 1.
  • char* argv[] — argument vector, an array of C-style strings. argv[0] is the program name. argv[1] is the first user-supplied argument.
  • argv[0]: contains the invoked program path. Application logic typically begins processing at argv[1].

Experiment: inspect argument passing. Create args.cpp:

// args.cpp -- print argc/argv
#include <iostream>
#include <string>
int main(int argc, char* argv[]) {
    std::cout << "argc = " << argc << "\n";
    for (int i = 0; i < argc; i++) {
        std::cout << "argv[" << i << "] = " << argv[i] << "\n";
    }
    return 0;
}
Line by line:
#include <iostream> — provides standard input/output facilities.
#include <string> — provides std::string.
int main(int argc, char* argv[]) — program entry point requesting command-line arguments from the OS.
std::cout << "argc = " << argc ... — writes the argument count to standard output. std::cout is the standard output stream; << is the insertion operator.
for (int i = 0; i < argc; i++) — iterates indices 0 through argc-1.
std::cout << "argv[" << i ... << argv[i] — prints each argument value.
return 0; — returns exit status 0 (success) to the OS.
g++ -std=c++17 args.cpp -o args
./args hello world "one more"
# Windows instead: .\args.exe hello world "one more"
Expected output: argc = 4, argv[0] = ./args, argv[1] = hello, argv[2] = world, argv[3] = one more. Quotation marks cause the shell to pass one more as a single argument. Omitting quotes splits it into two arguments, a common source of errors in todo add.

3. ANSI color output

Terminal color is controlled by ANSI escape sequences — non-printing character sequences interpreted as formatting instructions.

  • ANSI (American National Standards Institute) — defines the standard escape sequences recognized across terminal implementations.
  • Escape character \033 — the ESC byte (octal 033, hex \x1b). It introduces an escape sequence, indicating that subsequent characters specify formatting rather than printable text.
  • Examples: "\033[32m" selects green foreground. "\033[31m" selects red. "\033[1m" selects bold. "\033[0m" resets attributes to defaults. The reset sequence must be emitted after colored output.
  • Windows note: Windows Terminal supports ANSI sequences by default. Legacy cmd.exe does not. If escape sequences render as literal characters such as ←[32m, use Windows Terminal or the VS Code integrated terminal.
// color.cpp -- demonstrate ANSI output
#include <iostream>
#include <string>
const std::string GREEN = "\033[32m";
const std::string RED = "\033[31m";
const std::string BOLD = "\033[1m";
const std::string RESET = "\033[0m";
int main() {
    std::cout << GREEN << "This is green" << RESET << "\n";
    std::cout << RED << "This is red" << RESET << "\n";
    std::cout << BOLD << "This is bold" << RESET << "\n";
    return 0;
}
Line by line: The four const std::string declarations define named ANSI sequences (const indicates immutable). Each std::cout statement emits an enable sequence, text, the RESET sequence, and a newline (\n). Omitting RESET leaves subsequent terminal output formatted.

4. Filesystem organization with std::filesystem

The organizer classifies files by extension and relocates them into corresponding subdirectories. Filesystem refers to the OS abstraction for files and directories. std::filesystem (C++17) provides portable directory iteration, path manipulation, and file relocation.

  • File — a named data object (e.g. photo.jpg). Directory — a container for files (e.g. Images/). Path — a filesystem address (e.g. ./Downloads/photo.jpg).
  • Extension — the suffix following the final dot (.jpg, .pdf), indicating content type. path::extension() retrieves it.
  • directory_iterator — iterates entries within a single directory.
  • create_directories — creates a directory hierarchy if absent; no operation if it exists.
  • rename — relocates a file when source and destination reside on the same volume.

5. Design specification

Define behavior before implementation:

todo add "buy milk"     -> append "[ ] buy milk" to todos.txt
todo list               -> display numbered list with color formatting
todo done 2             -> change "[ ]" to "[x]" on line 2
todo clear              -> remove all lines marked [x]
organize ./Downloads    -> categorize files by extension into Images/Docs/...
Specification notes: -> denotes the resulting operation. todos.txt is a flat-file store with one task per line ([ ] = pending, [x] = completed). The organizer accepts a directory path argument.

6. Todo application — full implementation

// todo.cpp -- g++ -std=c++17 todo.cpp -o todo
#include <iostream>
#include <fstream>
#include <vector>
#include <string>
const std::string GREEN = "\033[32m";
const std::string RED = "\033[31m";
const std::string RESET = "\033[0m";
const std::string BOLD = "\033[1m";
const char* DB = "todos.txt";

std::vector<std::string> load() {
    std::vector<std::string> v;
    std::string line;
    std::ifstream in(DB);
    while (std::getline(in, line)) {
        if (!line.empty()) v.push_back(line);
    }
    return v;
}
void save(const std::vector<std::string>& v) {
    std::ofstream out(DB, std::ios::trunc);
    for (auto& l : v) out << l << "\n";
}
int main(int argc, char* argv[]) {
    if (argc < 2) {
        std::cout << "Usage: todo add \"task\" | list | done N | clear\n";
        return 1;
    }
    std::string cmd = argv[1];
    auto v = load();
    if (cmd == "add") {
        if (argc < 3) {
            std::cout << RED << "missing task\n" << RESET;
            return 1;
        }
        v.push_back("[ ] " + std::string(argv[2]));
        save(v);
        std::cout << GREEN << "Added!\n" << RESET;
    } else if (cmd == "list") {
        if (v.empty()) std::cout << "No todos. Add one!\n";
        for (size_t i = 0; i < v.size(); i++) {
            std::cout << BOLD << (i + 1) << ". " << RESET << v[i] << "\n";
        }
    } else if (cmd == "done") {
        int n = std::stoi(argv[2]);
        if (n < 1 || n > (int)v.size()) {
            std::cout << RED << "bad number\n" << RESET;
            return 1;
        }
        if (v[n - 1][1] == ' ') v[n - 1][1] = 'x';
        save(v);
        std::cout << GREEN << "Done!\n" << RESET;
    } else if (cmd == "clear") {
        std::vector<std::string> keep;
        for (auto& l : v) {
            if (l.size() < 2 || l[1] == ' ') keep.push_back(l);
        }
        save(keep);
        std::cout << "Cleared completed.\n";
    } else {
        std::cout << RED << "unknown command\n" << RESET;
    }
    return 0;
}
Part A — headers and constants:
#include <iostream> — standard output. #include <fstream> — file streams for persistent storage. #include <vector> — dynamic array container. #include <string> — text string type.
Color constants define ANSI enable/reset sequences.
const char* DB = "todos.txt"; — path of the persistent task store, located adjacent to the executable.
Part B — load(): read persistent state into memory:
std::vector<std::string> load() returns the stored lines.
std::ifstream in(DB); opens the file for input. If the file does not exist, the resulting vector is empty.
while (std::getline(in, line)) reads one line per iteration.
if (!line.empty()) v.push_back(line); discards empty lines and appends valid entries.
return v; returns the populated vector.
Part C — save(): write memory state to disk:
void save(const std::vector<std::string>& v) returns nothing. The parameter is a const reference: no copy, read-only access.
std::ofstream out(DB, std::ios::trunc); opens the file for output with trunc (truncate existing content).
for (auto& l : v) out << l << "\n"; writes each entry followed by a newline.
Part D — main(): dispatch on argv:
if (argc < 2) detects invocation without a command, prints usage, and returns 1 (error status).
std::string cmd = argv[1]; copies the command into a std::string for comparison.
auto v = load(); loads stored tasks; all commands operate on v and persist via save.
add: validates argc < 3, appends "[ ] " + task, saves, and confirms.
list: reports empty state or iterates with index i, printing 1-based numbering (i+1).
done: std::stoi(argv[2]) converts the numeric argument to int. Validates range, then modifies character index 1 from ' ' to 'x' (transition from [ ] to [x]).
clear: constructs vector keep containing only pending entries and saves it, removing completed tasks.
The trailing else handles unrecognized commands such as todo lst.
Architectural pattern: load state into memory, mutate the in-memory representation, then persist. This load-modify-save sequence applies to most file-based utilities.

7. File organizer — full implementation

// organize.cpp -- g++ -std=c++17 organize.cpp -o organize
#include <filesystem>
#include <iostream>
#include <map>
#include <string>
namespace fs = std::filesystem;
int main(int argc, char* argv[]) {
    fs::path dir = (argc > 1) ? argv[1] : ".";
    std::map<std::string, std::string> m = {
        {".jpg", "Images"}, {".png", "Images"},
        {".pdf", "Docs"}, {".txt", "Docs"},
        {".mp3", "Audio"}, {".wav", "Audio"},
        {".zip", "Archives"}, {".cpp", "Code"}
    };
    for (auto& e : fs::directory_iterator(dir)) {
        if (!e.is_regular_file()) continue;
        std::string ext = e.path().extension().string();
        auto it = m.find(ext);
        if (it == m.end()) continue;
        fs::path dest = dir / it->second;
        fs::create_directories(dest);
        fs::rename(e.path(), dest / e.path().filename());
        std::cout << "moved " << e.path().filename()
                  << " -> " << it->second << "\n";
    }
    return 0;
}
Line by line:
#include <filesystem> — directory and path facilities (C++17). #include <map> — associative container mapping extension to directory name.
namespace fs = std::filesystem; — namespace alias for concise qualification.
fs::path dir = (argc > 1) ? argv[1] : "."; — target directory defaults to "." (current working directory). The conditional operator implements the default.
std::map ... m = {...} — classification table mapping extensions to destination names.
for (auto& e : fs::directory_iterator(dir)) — iterates each entry in the target directory.
if (!e.is_regular_file()) continue; — restricts processing to regular files, skipping directories. continue advances to the next entry.
std::string ext = e.path().extension().string(); — extracts the extension (e.g. .jpg). Matching is case-sensitive.
auto it = m.find(ext); if (it == m.end()) continue; — looks up the extension; skips unlisted types (end() indicates absence).
fs::path dest = dir / it->second; — constructs the destination path. operator/ appends a path component.
fs::create_directories(dest); — ensures the destination directory exists.
fs::rename(e.path(), dest / e.path().filename()); — relocates the file, preserving the filename.
The final output statement reports each relocation.
Verification practice: test on a copy first. Create directory testmess with sample files (a.jpg, b.pdf, c.txt) and execute organize ./testmess. Validate behavior before operating on production directories.

8. Compiling and running

cd $HOME\Documents\CppCourse
# Mac / Linux:

# Step 2: compile (identical across platforms)
g++ -std=c++17 todo.cpp -o todo
g++ -std=c++17 organize.cpp -o organize

# Step 3: exercise the todo application
./todo list
./todo add "buy milk"
./todo add "read 10 pages"
./todo list
./todo done 1
./todo list
./todo clear
# Windows: replace ./todo with .\todo.exe (same for organize)
Compiler invocation: g++ invokes the C++ compiler. -std=c++17 selects the C++17 standard (required for std::filesystem). todo.cpp specifies the translation unit. -o todo sets the output executable name. Execution consists of invoking the resulting binary. A 'g++' is not recognized diagnostic indicates the compiler is not on PATH; open a new terminal and verify installation per Lesson 01.

Expected session: initial list reports no tasks. After two add operations, list displays 1. [ ] buy milk and 2. [ ] read 10 pages. After done 1, entry 1 shows [x]. After clear, only pending entries remain. Inspecting todos.txt confirms the persistent representation.

9. Troubleshooting

SymptomCauseResolution
missing task despite providing inputUnquoted multi-word task caused shell splitting: todo add buy milk passes argv[2]=buy separately from milk.Quote multi-word arguments: todo add "buy milk".
bad numberIndex out of range, or non-numeric input to stoi (e.g. done two).Execute list first, then supply the displayed numeric index. stoi requires digit input.
Literal sequences like [32m instead of colorsTerminal does not interpret ANSI sequences.Use Windows Terminal or VS Code terminal. Color output is optional; program logic is unaffected.
No such file for organizeInvalid directory argument.Verify with directory listing, correct the path, or pass . for the current directory.

✅ Exercises

  1. Argument quoting: execute args with quoted and unquoted multi-word input. Record how argc changes and explain the difference.
  2. Edit command: implement todo edit 2 "new text" to replace line 2 with [ ] new text. Adapt the done block, replacing the full string rather than a single character.
  3. Dry-run mode: add a --dry-run option to the organizer that prints prospective moves without calling rename. This is standard practice for validating destructive operations.
  4. Operation log: after each add/done/clear, append an entry to app.log. Hint: std::ofstream log("app.log", std::ios::app); log << ...; (app = append mode).
  5. Due dates: extend the record format to [ ] 2026-10-20 buy milk. Design how list would identify overdue entries. Outline the comparison logic before implementing.
